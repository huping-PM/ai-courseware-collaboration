# 文字稿 → PPT → 讲解视频 · 量产流程清单

> 用途：换电脑、换账号都能照着跑通的标准化生产流程。
> 实测样本：《非车险综合治理政策解读》25 页 PPT + 7 分 56 秒动画视频（无字幕）。
> 全文参数均为**实测值**，不是估算。

---

## 0. 总览：一条流水线，8 个环节

```
①文字稿          ②结构化文案        ③配图           ④PPT
 docx/讲稿  ──▶  PAGES 数据  ──▶  20 张 PNG  ──▶  25 页 .pptx
 (LLM 提炼)      (LLM 改写)       (ImageGen)     (slidep)
                                                      │
                      ⑤配音 ─▶ ⑥动画HTML ─▶ ⑦逐帧渲染 ─▶ ⑧合成成片
                     (edge-tts)  (Python)   (Edge+pptr)  (ffmpeg)
                                                      │
                                              三套审计 PASS ──▶ 交付 .mp4
```

**两条主线**：`文案线`（①→④）产出 PPT；`视频线`（⑤→⑧）产出视频。
**关键设计**：视频线的画布内容**直接 import 文案线的 PAGES 数据**，所以「视频 == PPT」是结构性保证，不靠人工比对。

## 2. 环节 ①：文字稿 → 结构化文案（PAGES）

| 项 | 内容 |
|---|---|
| **输入** | docx 原文 / 讲稿 / 政策文件 |
| **输出** | `_gen_slides20.py` 里的 `PAGES` 列表（25 个 dict） |
| **用到的模型** | WorkBuddy 对话大模型（文本提炼与改写） |
| **用到的技能** | 无（直接用模型对话） |
| **工具** | Python `zipfile` + `re` 提取 docx 正文 |

**PAGES 每页的数据结构**：

```
{
  "n": 页码, "title": "页标题(≤14字)", "type": "布局类型",
  "lead": "导语(1句)", "cards": [...], "conclude": "小结条",
  "img": "assets_opt/xxx.jpg", "notes": "该页口播稿(写入演讲者备注)"
}
```

### 提示词模板（文案提炼）

```
你是金融监管政策解读的资深文案。给定原文，产出 N 页 PPT 文案 + 每页口播稿。

硬性要求：
1. 每页只讲一个核心观点；页标题 ≤ 14 字，动词开头或名词短语。
2. 每页要点 3~5 条，每条 ≤ 22 字；有小结条的页,小结 ≤ 26 字。
3. 不得照抄原文：与原文相似度 ≥ 0.80 的句子必须改写为关键词式表达。
   例外：章节标题、"四项基本原则"这类必须原样保留的专有提法。
4. 单页正文总字数 ≤ 110 字（20pt 字号下版心容量上限）。
5. 长内容拆多页，不许压缩字号硬塞。
6. 同步输出该页口播稿：口语化、拆成逐句，每句 12~30 字，
   句子边界要落在语义停顿处（后面配音与动效都按句对齐）。

输出格式：JSON 列表，字段 n/title/type/lead/cards/conclude/img/notes。
```

### 限制条件
- **单页字数红线 110 字**：超过必然溢出版心（20pt 下 528px 只装得下这些）。
- 相似度 ≥ 0.80 必须改写，否则是"照搬原文"。
- 口播稿句子长度 12~30 字：太短则动效碎、太长则单句停顿久。

## 4. 环节 ③：PPT 生成

| 项 | 内容 |
|---|---|
| **输入** | `slides20/NN.slide`（SlideDSL 源）+ `assets_opt/*.jpg` |
| **输出** | `xxx.pptx`（25 页 + 25 个演讲者备注） |
| **用到的模型** | 无（模板化生成，保证风格 100% 一致） |
| **用到的技能** | **`tencent-docs-routing` → `tencent-pptx`**（必先路由再调用） |
| **备选技能** | `ppt-master`（用户级，另一套生成器） |

### 核心命令

```bash
node <slidep>/dist/index.js create "<out>.pptx"
node <slidep>/dist/index.js upsert-dsl "<out>.pptx" --dsl-file slides20/NN.slide --page-index -1
# 注意：目标 pptx 是位置参数，源文件必须用 --dsl-file
```

### ★ 字号换算（最容易错的一环）

```
pptx 实际尺寸 = 12192000 × 6858000 EMU = 13.333in × 7.5in
slide 源码画布 = 1280 × 720 px，1px = 1/96 in
∴ 20pt = 20/72 in = 20/72 × 96 = 26.667 px（源码里写 26.7）
```

| 角色 | pt | 源码逻辑px |
|---|---|---|
| 正文 | 20pt | 26.7 |
| 卡片/小节标题 | 21.75pt | 29 |
| 页标题 | 25.5pt | 34 |
| 巨型锚点 | — | 96 |

> **血泪坑**：把 `20`（pt 数值）直接当逻辑 px 传给 `px()` → 实际只有 30px 而不是 40px，**小了 25%**。必须用换算后的值。

### 版式与几何标准（必须与 PPT 一致）

| 项 | 标准值（1280×720 逻辑 px） |
|---|---|
| 页面 padding | 上 24 / 左右 64 |
| A 标题区 | y 0–112，高 112 |
| B 内容区（版心） | **left 64, top 112, width 1152, height 528** |
| C 页脚条 | y 664–720，高 56 |
| 内容底边 | 112 + 528 + 56 = **696** |

行高（**必须照抄 PPT，不能"看着差不多"**）：标题 1.2 / 卡片标题 1.25 / 正文 1.5 / 行标题与描述 1.4 / 胶囊 1.35 / 时间线 1.35·1.55。

### 演讲者备注注入（踩坑点）

slidep 生成的 pptx **只有 notesMaster 空壳，没有 notesSlide body 占位符**，高层 API 全部失效：
- `slide.notes_slide.notes_text_frame` → `None`
- `NotesSlideShapes` 没有 `add_textbox` 方法

**解法**：用 `lxml` 直接构造 `<p:sp>` 插进 notesSlide 的 `spTree`（一个空 body 占位符 + 一个正文文本框，run 的 `sz="1200"` = 12pt）。脚本要幂等（注入前先清空已有 sp）。

### 检查
- `slidep validate` → 25/25 无溢出
- 备注覆盖：句数/字数零遗漏（实测 49/49 句、2232/2232 字）

### ⚠️ validate 有盲区
`slidep validate` 只比对画布 720px，且根节点 `overflow:hidden` 会裁掉越界内容 →
**内容超出 528px 版心压到页脚时，validate 依然报 ready**。
实测 p02 超 36px、p03 超 34px 时仍全绿。**只有渲染像素可信**。

内容安全预算（排版前先算）：
```
content 528 = lead(≈46) + banner + 卡片/行区 + 结论条(≈61) + gap 累加
单卡高：card()≈200px、card_compact()≈146px、结论条≈61px
带结论条的页：banner ≤ 104px（或改"左图右内容"布局）
```

## 5. 环节 ④：配音合成（TTS + timeline.json）

| 项 | 内容 |
|---|---|
| **输入** | 每页口播稿（逐句拆分） |
| **输出** | `audio/pages/page_NN.wav` + `timeline.json` |
| **用到的模型** | **edge-tts 神经网络 TTS**（不是 LLM） |
| **音色** | `zh-CN-YunyangNeural`（专业男声） |
| **备选技能** | `local-tts`（Intel 本地 TTS，离线，换音色/克隆声音时用） |

### 代码骨架

```python
import edge_tts
async def synth(text, out):
    await edge_tts.Communicate(text, "zh-CN-YunyangNeural", rate="+0%").save(out)
```

### 参数标准

| 参数 | 值 | 说明 |
|---|---|---|
| 段间停顿 `PAUSE` | 0.25s | 句与句之间 |
| 页尾余量 `TAIL` | **0.30s** | 三处必须一致：`build_pages25.py` / `render25.js` / `build_video25.py` |
| 采样率/声道 | 44100Hz / 立体声 / 16bit | 全流程统一 |

### timeline.json 结构（全流程的**单一数据源**）

```json
{
  "voice": "zh-CN-YunyangNeural",
  "tail": 0.3,
  "pages": {
    "1": { "total": 13.388,
           "segs": [{"start":0.0,"dur":3.56,"text":"..."}, ...] }
  }
}
```

### 限制条件（重要）
1. **必须后台运行**：70+ 段合成在前台会超时被 SIGTERM。脚本要**幂等**（已存在则跳过）。
2. 时长要用 `mutagen` 读 mp3 **真实时长**，不能按字数估算。
3. **改音色会改变所有时长** → 必须重跑 timeline 与后续全部环节。
4. `total`（wav 实测长）≠ `narr_end`（最后一句语音结束）：部分页 wav 尾部有 0.25s 静音。
   **凡"锚在页长"的时序逻辑都是错的，要锚 `narr_end`。**

## 6. 环节 ⑤：动画 HTML 生成

| 项 | 内容 |
|---|---|
| **输入** | `PAGES`（环节①产物）+ `timeline.json`（环节⑤产物） |
| **输出** | `html/pages/p01..p25.html`（1920×1080 动画页） |
| **用到的模型** | 无（纯模板 + 算法） |
| **用到的技能** | **`ppt-to-animated-video`**（本项目沉淀，含全部参考脚本） |
| **关键脚本** | `build_pages25.py` |

**动效模型**：所有元素**只用 opacity 淡入**（0→1，0.62s），不带位移/缩放。
DOM 上由 `window.seek(t)` 做**确定性时间跳转**（渲染时逐帧调用即可复现任意时刻画面）。

### ★ 音画同步算法（核心，也是全流程最难的部分）

元素淡入时刻 = **它所属那一句旁白的时间区间内**，且硬上限「句尾 − 0.45s」。

| 常量 | 值 | 作用 |
|---|---|---|
| `LAG` | 0.45s | 元素最晚须在句尾前 0.45s 出现 → 杜绝"读完才出现" |
| `FADE` | 0.62s | 单元素淡入时长 |
| `PAGE_IN` | 0.55s | 页首整层淡入 |
| `TAIL` | 0.30s | 页尾余量 |
| `BLK_MIN` | 3 字 | 公共块 ≥3 字才认定"旁白真念到了" |
| `SC_MIN` | 0.62 | **弱匹配门槛**，低于此不锚定、改句内铺开 |
| `MONO_MAX` | 1.5s | 顺序修正让步上限，超了就"忠实配音"不强拗 |

**锚定算法**：用 `difflib.SequenceMatcher` 求"元素文本 × 该句旁白"的公共块，
取**句中最早的实质片段**作为锚点（不要求命中元素开头）。
匹配不成功 → 在前后锚点之间**按顺序铺开**。

### 页尾淡出（两个必错点）
1. 淡出**起点**必须锚 `narr_end`（最后一句说完），不能锚 `total`（含静音尾）——
   否则讲话时画面就开始变暗。
2. 淡出**终点**必须锚 `total + TAIL`（片段末帧）——否则每页末尾留 0.3s 空白帧。
3. **页头/页脚层必须并入同一条淡出曲线**，否则末帧残留标题与分隔线。

### 自检（必须为 0）
```
[sync] N 个淡入节拍，0 越过句尾
[sync] 一句内 ≥3 个元素压在 0.35s 内 —— 0 处
```

## 7. 环节 ⑥：逐帧渲染

| 项 | 内容 |
|---|---|
| **输入** | `html/pages/*.html` |
| **输出** | `html_frames2/pNN/f00000.png …`（实测共 11903 帧） |
| **用到的模型** | 无 |
| **用到的技能** | 无（`render25.js`） |
| **引擎** | Edge headless + `puppeteer.connect` |

**做法**：启动 Edge（headless=new，固定随机端口）→ puppeteer 连接 → 对每页
`page.goto(file://)` → 循环 `window.seek(f/25)` → `page.screenshot()`。

### 参数
| 项 | 值 |
|---|---|
| 分辨率 | 1920 × 1080 |
| 帧率 | 25 fps |
| 帧数 | `round((total + 0.30) × 25)` |
| 耗时 | 约 **80s ~ 2.5 分钟/页**（25 页约 33 分钟） |

### 限制条件
1. **改生成器后必须全量重渲**：`render25.js` 是**逐页从磁盘读 HTML** 的。
   若在渲染途中改了 `build_pages25.py`，已渲页与未渲页会来自不同版本 → 整批作废。
2. **不要用 `-loop 1` 类旧法**：本项目用逐帧截图，帧率天然确定。
3. 输出文件名直接写成 ffmpeg 规范 `f%05d.png`，重渲**原地覆盖**（沙箱禁用批量删除）。
4. **并发会撞端口**：多脚本同时 spawn Edge 会报 `HTTP Unauthorized`；串行执行。

## 8. 环节 ⑦：合成成片

| 项 | 内容 |
|---|---|
| **输入** | 帧目录 + 每页 wav |
| **输出** | `xxx（动画版·无字幕）.mp4` |
| **用到的模型** | 无 |
| **用到的技能** | 无（`build_video25.py`） |
| **工具** | ffmpeg 7.1（imageio-ffmpeg 提供） |

### 三个子阶段

```bash
PY build_video25.py pages    # 逐页：帧 + 音频 → page_NN.mp4
PY build_video25.py concat   # 拼接（-c copy）
PY build_video25.py final    # +faststart 出成片
PY build_video25.py all      # 一条龙
```

### 关键参数
```
-framerate 25 -i f%05d.png -i page_NN.wav -frames:v <want>
-vf scale=1920:1080,format=yuv420p
-af apad  -c:v libx264 -preset medium -crf 18  -c:a aac -b:a 192k -shortest
```

| 项 | 值 |
|---|---|
| 编码 | h264 High / yuv420p / crf 18 |
| 音频 | aac 192k / 44100Hz / 立体声 |
| 限帧 | `-frames:v round((total+0.30)×25)` —— **必须显式限帧** |

### 限制条件
1. **必须显式限帧**：否则页长变短时会继续读旧的长页残帧 → 视频尾部画面错乱。
2. **必须强制重建每页 mp4**：跳过已存在文件会误用旧片段。
3. 无字幕版只需 `-c copy` remux（秒级），不要顺手多产字幕文件。

## 9. 环节 ⑧：三套审计（交付前必跑）

| 脚本 | 查什么 | 通过线 |
|---|---|---|
| `verify_sync25.py` | **音画同步** | 提前 0 / 滞后 0 / **挤堆 0** / 倒挂 0 |
| `verify_final_boundaries.py` | 25 个页面边界 | 讲完前墨量=峰值、段末墨量=0.0000 |
| `verify_video25.py` | **成片端到端**（6 组） | 见下表 |

`verify_video25.py` 六组：

| 组 | 内容 | 通过线 |
|---|---|---|
| A 容器/流 | 分辨率/帧率/编码/字幕流 | 1920×1080 / 25fps / h264+aac / 无字幕流 |
| B **帧数** | 逐页帧数与成片帧数 vs `Σ round((total+TAIL)×25)` | **逐帧严格相等** |
| C 像素保真 | **分页 mp4** 取帧 vs 已审计 HTML 帧 | 平均绝对差 ≤ 6.0/255 |
| C2 拼接无损 | 成片 vs 分页 mp4 同刻帧 | 差 ≈ 0 |
| D 页尾时序 | 讲完前饱满、段末淡净 | 25/25 |
| E 视觉保真 | 字号/行高/配色/版心是否只剩 PPT 档位 | 无越档值 |

### ★ 两个测量陷阱（踩过，务必避开）

1. **拿容器时长判节奏 → 假失败**。逐页 mp4 用 `apad` 补音轨，AAC 帧长 23.2ms，
   音轨补给到 AAC 帧边界 → 个别页容器时长长出 ~0.07s（本次 p4），
   成片容器 476.21s 而**视频流只有 476.12s**。**帧数才是节奏的唯一真相**。
2. **在 concat 成片上用 `-ss` 取帧 → 假失败**。拼接后定位有 ~2 帧系统偏移
   （表现为最佳匹配帧恒定落在 `fi-2`）。
   **C 组必须在分页 mp4 上取帧**；成片画面对错由 C2 组背书。

### 审计器自身要防的盲区
- 只查"提前/滞后/倒挂"会漏掉**挤堆**（全部元素相等 → 三项都判通过）。
  **必须加挤堆判据**：一句内 ≥3 个元素落在 0.35s 窗内即报错。
- 判提前/滞后前必须先卡 `score ≥ SC_MIN`，否则拿弱匹配的不可靠位置当基准 → 一堆假阳性。

## 10. 标准速查（所有"数"集中在这里）

### 10.1 画布与换算

| 项 | PPT 源 | 视频 |
|---|---|---|
| 画布 | 1280×720 逻辑px（13.333×7.5in） | 1920×1080（S = 1.5） |
| 换算 | 1 逻辑px = 1/96 in；20pt = 26.667 逻辑px | **视频物理px = pt × 2.0** |
| 版心 | 64, 112, 1152, 528 | **96, 168, 1728, 792** |
| 帧率 | — | 25 fps |

### 10.2 字号档位（只允许出现这些值）

视频物理 px：`144 / 51 / 43.5 / 40.05 / 39 / 36 / 33 / 31.5 / 27`
对应：巨型锚点 / 页标题(25.5pt) / 卡片标题(21.75pt) / 正文(20pt) / 图标 / … / 页脚

### 10.3 行高档位（只允许这些）

`1 / 1.2 / 1.25 / 1.35 / 1.4 / 1.5 / 1.55`

映射：页标题 1.2 / 卡片标题 1.25 / 正文 1.5 / 行标题·描述 1.4 / 胶囊 1.35 / 时间线 1.35·1.55 / 巨型锚点 1.0

### 10.4 配色（只允许这些）

| 角色 | HEX |
|---|---|
| 主色·淡绿 | `#34C77B` |
| 深色·墨绿 | `#0F3D2E` |
| 浅底·雾绿 | `#E8F7EF` |
| 中性·石墨 | `#5B6B63` |
| 辅助 | `#FFFFFF` / `#F7FBF8` / `#EAFBF2` |
| 渐变深阶 | `#1F9D5F` |

**禁止**：绿底白字卡片、emoji、多套图标风格混用、装饰位置漂移。

### 10.5 文字密度门禁

| 页型 | 最少元素 | 正文字数下限 | 配图数 |
|---|---|---|---|
| 单主题内容页 | 标题+正文+主视觉 | ≥ 180 | 1 |
| 卡片组页 | 标题+引导句+N 卡 | 每卡 ≥ 70（合计 ≥ 210） | 0–N |
| 数据/锚点页 | 标题+主锚点+洞察 | ≥ 80 | 1 |

- 常规页留白 ≤ 35%；卡片内容垂直填充率 ≥ 85%
- 单页正文（20pt）字数 ≤ 110 字

### 10.6 时序常量

| 常量 | 值 | 归属 |
|---|---|---|
| PAUSE（句间停顿） | 0.25s | 配音 |
| TAIL（页尾余量） | **0.30s** | 生成/渲染/合成三处一致 |
| FADE（元素淡入） | 0.62s | 动效 |
| PAGE_IN（整页淡入） | 0.55s | 动效 |
| LAG（最晚出现余量） | 0.45s | 同步 |
| BLK_MIN / SC_MIN / MONO_MAX | 3 字 / 0.62 / 1.5s | 同步 |

## 12. 踩坑速查

| 现象 | 根因 | 解法 |
|---|---|---|
| 画面文字明显比 PPT 小 | 把 pt 数值当逻辑 px | 用换算后的 26.7，或直接 import 常量 |
| 字号对了但内容压住页脚线 | 行高/版心与 PPT 不一致 | 照抄 PPT 行高与 `top=112/height=528` |
| validate 全绿但渲染溢出 | validate 只比画布、overflow 裁掉越界 | **只有渲染像素可信** |
| pptx 导出 500/504 | 嵌入 2MB PNG 导致包 41MB | **先压 JPEG**（长边 1280 / q84） |
| edge-tts 前台被 SIGTERM | 段数多、前台超时 | 后台运行 + 幂等 |
| 配音读完文字才出现 | 锚点用了"包含该时刻的句子"或页尾 | 用**锚点句归属** + `LAG` |
| 配音没念到文字就先冒出来 | 只按句子序号排 | **内容级锚定**（diff 公共块） |
| 整页文字卡住不动后一起冒出 | 匹配失败仍返回大 `blk`；或要求命中元素开头 | `blk` 归零 + 取**最早实质片段** + `SC_MIN` |
| 元素被拖到句尾 | 概括句在旁白尾巴偶合 | `SC_MIN` 门槛 + `MONO_MAX` 让步上限 |
| 审计 PASS 但视频明显糊在一起 | 审计漏掉"挤堆" | 加挤堆判据 |
| 讲话时画面变暗 | 淡出锚 `total`（含静音尾） | 改锚 `narr_end` |
| 每页末 0.3s 空白页 | 淡出终点早于片段末帧 | 终点锚 `total + TAIL`，页头并入同曲线 |
| 视频尾部画面错乱 | 残留旧长页帧 | ffmpeg `-frames:v` 限帧 |
| 报"成片时长差 0.09s" | 拿容器时长判据 | 改判**视频流帧数** |
| 像素校验差 14~22，分页只差 1.5 | 在 concat 成片上 `-ss` 取帧 | 改在**分页 mp4** 取帧 |
| 并发 headless 报 Unauthorized | 端口撞车 | 串行 + 随机端口 |
| 拆页后时长差几十毫秒 | ffmpeg `-c copy` 取整 | 用 `wave` 模块**样本级**切片 |
