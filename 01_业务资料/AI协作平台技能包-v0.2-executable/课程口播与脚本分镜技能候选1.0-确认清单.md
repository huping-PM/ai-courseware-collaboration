## 2. 已提炼的稳定共识

### 2.1 课程内容与口播

- 一课解决一个具体判断问题，知识点不超过 3 个，推荐总时长 8–10 分钟。
- 成稿不是大纲，而是可直接录制的完整旁白、对白或讲师口播。
- 必备结构：题目、对象、目标、核心结论、制作说明/角色、场景演绎、知识讲解、栗子精灵小结、8 道练习、编审说明与资料来源。
- 知识主体采用“先判断 A，再判断 B，最后核实 C”；每个判断点在口播中讲清结论、条件、误区、服务动作和依据。
- 场景只引题；知识讲解后直接进入栗子精灵小结，不回开场人物，不补写办理结果；小结不超过 150 字。
- 每课 8 道题，建议 3–4 道单选、4–5 道判断；均附答案、解析和依据。

### 2.2 情境导入与场景资产

- 导入目标是暴露一个自然误解或业务难题，不替代正文讲规则；时长 60–90 秒。
- 固定叙事骨架：日常铺垫 → 风险/认知冲突 → 现实压力或关键矛盾 → 冻结问题 → 课程收口。
- 可选表达版本：叙事版、V3 对话版、融合版。必须记录选择方式、理由和确认人；对话用于自然暴露误解，叙事适合情绪氛围、动作画面或政策概念引入。
- 场景库目前覆盖 14 套人身、财产、政策主题场景，涵盖痛点暴击、认知打脸、双人对比、细节沉浸、悬念钩子和知识点闭环等叙事模型。
- 制作禁忌：无血腥/死亡重症/极端事故画面；无真实保险公司标识、夸张金额、营销承诺；政策类不特写公章和完整文号；人物表演克制、生活化。

## 4. 平台需要承接的最小数据契约

### 4.1 任务输入

```text
course_request: 课题、对象、学习目标、核心问题、交付形态
source_packet: source_id、文件版本/哈希、已核实事实、待核实事项、不可承诺事项
scene_choice: 场景 ID 或“新建”、叙事/V3/融合版、选择理由、确认人
course_template: 本课程类型、时长范围、角色与品牌/制作限制
```

### 4.2 阶段成果与状态

```text
N04 manuscript_draft      = 完整口播稿 + 来源定位
N05 review_result         = P0–P3 问题单 + 通过/修改后复审/退回上游
N05 manuscript_confirmed  = 锁定版本，供 N06 唯一引用
N06 scene_storyboard      = 场景资产 + 节拍 + 镜头卡
N06 lesson_storyboard     = 来源口播段 + 页面/镜头 + 屏幕文字 + 制作提示
```

每个成果须保存：任务 ID、版本号、负责人、确认时间、上游成果版本和 `source_id`。N06 的每页/每镜都应回链 N05 的来源口播段；任何实质口播修改自动回退 N05。

## 5. 需要从旧规则拆出的边界

旧 Markdown 的“输出可制作分镜”要求，和当前“先文稿、后脚本分镜”的平台流程混在一起。候选 1.0 的处理是：

- **保留在 N04：** 课程完整口播、场景文字化设计、对白/旁白、信息呈现意图、8 道题和来源。
- **移至 N06：** 镜号、时长、机位、画面、页面编号、屏幕文字、动效、数字讲师安全区、素材/资产、AI 生成提示词和可制作性检查。
- **处理 PDF 的“镜头不锁死”：** N04 只锁定导入目的和口播；N06 在 60–90 秒总时长和场景禁忌内弹性拆镜，而不强制旧规则中的固定镜头数。
