# 音画同步算法与踩坑记录

## 1. 唯一真相：timeline-full.json

配音合成（`synth_full.py`）时，逐句写入每句 `dur`（实测秒数），场景内按序累加得出每句 start。这是动画入场时刻的唯一对齐基准。

```json
{"scenes": {"s05": {
  "segs": [
    {"i":0, "text":"二、强化产品源头管理。", "file":"s05_s00.mp3", "dur":3.12},
    {"i":1, "text":"制造企业新增设备…",      "file":"s05_s01.mp3", "dur":11.304},
    …
  ],
  "total": 30.528
}}}
```

关键：`total` 必须等于该场所有句 dur 之和（= 该段配音实测时长），也必须是 index.html 里该场的 `data-duration`。

## 2. 对齐规则

每个卡片/板块的入场时刻 `at` = 它对应的那句旁白的「场景内相对 start」（即前面所有句 dur 之和 + 微小正偏移 0~0.2s）。

例：scene09（数据三支柱）三句旁白起点：

| 板块 | 对应旁白句 | 场景内 start | 动画 at |
|---|---|---|---|
| 优化数据标准 | i2「首先，优化行业数据标准…」 | 11.784 | 12.0 |
| 加快系统建设 | i4「其次，加快系统建设…」 | 32.712 | 32.9 |
| 强化积累使用 | i6「同时，强化数据积累和使用…」 | 49.104 | 49.3 |

**红线**：多卡片场景（三举措/三支柱/三主体/三保障）是最容易全错的地方——旧版把三张卡分别写 8.8/15.6/32.4 这种拍脑袋值，跟真实旁白起点（1.0/15.5/32.1）偏离巨大，导致「配音讲到第二个板块了，第一张卡才刚弹出」。

## 3. 脚本：calc_seg_times.py

`scripts/calc_seg_times.py` 读 timeline-full.json，打印每场每句的「场景内 start/end」，直接作为写 `tl.fromTo(..., at)` 的对照表。用法：

```bash
python scripts/calc_seg_times.py <timeline-full.json> [场景id]
```

不传场景 id 打印全部；传 `s09` 只打印该场。

## 4. 其他踩坑

- **并行 Edit 会丢失更新**：同一文件两处独立的 Edit 若并发提交，可能一个覆盖另一个。对同一文件的多次修改要**串行**或合并成**一次原子大块 Edit**（本项目 scene05 文字 y 值因并行改坏，触发 content_overlap error）。
- **单卡片/线性场景（时间线、对比+分支）** 往往本就和旁白吻合，优先排查「多卡片并列」场景。
- **SVG 文字居中**：`<text>` 默认 `text-anchor="start"`，会右偏移；居中要在标签上加 `text-anchor="middle"`，且 x 取元素几何中心。
- **卡片内文字居中**：给卡片 div 加 `text-align:center`，图标用 `margin:0 auto`（或 flexible 容器居中）。
- **标题与序号同行 + 标题居中**：容器 `position:relative`，左元素 `position:absolute;left:0`，标题 `position:absolute;left:0;right:0;text-align:center`，三元素同一行高垂直居中。

## 5. 验收

1. 打开成片，逐板块听——每个板块的画面应在旁白念到它的瞬间（而非念完）出现。
2. 重点看多卡片场景：业务经营三方面、数据三支柱、中介三主体、三大保障。
3. 若仍有某段落不同步，只调该场景该卡片的 `at`（场景内相对秒，不要被全片绝对秒绕晕）。改完重跑 check + 重渲染（渲染很贵，尽量一次改对）。
