# AI课件协作平台：课件编辑器需求说明

版本：v0.1｜日期：2026-09-20｜状态：需求设计草稿，待评审；未排期、未实现。

关联需求：沿用R08制作工作台，扩展R04视听制作、R05返工、R09成果保存；衔接R07任务管理、R11项目隔离、R14工具接入、R15质量与R19计量，不新增重复的R需求域。

本文是课件编辑器专题需求主本。依据为[9月20日群聊及截图](../01_业务资料/外部材料/2026-09-20-课件编辑器/聊天记录与截图依据.md)、[业务共识](../02_需求与共识/AI课件协作平台-业务流程与需求共识.md)、[内容协作智能体需求](内容协作智能体-需求说明.md)和[任务与数据统计需求](协作任务、数据看板与权限-需求说明.md)。群聊的明确诉求与本稿的产品设计建议分别标注；文档起草不表示首版范围或实现方案已确认。

## 1. 业务需求分析

### 1.1 聊天记录表达了什么

| 依据 | 明确诉求或观察 | 对本平台的需求含义 | 证据边界 |
|---|---|---|---|
| 朱萍萍14:30“生成后预览直接进入这个界面，可以在这里调整”；朱丹14:31“编辑工作台” | 生成后可进入工作台预览和调整 | 生成成果应能继续编辑，避免每次修改都重新制作整份课件 | 未明确所有成果类型、自动跳转条件和具体可编辑属性 |
| 朱萍萍14:31“确认后就可以导出视频” | 用户确认后输出视频 | 区分工作中的工程与最终视频，导出需要固定确认版本 | 此处确认未明确为主管审核，不能替代既有任务审核 |
| 朱萍萍14:31“也可以在对话框直接提出修改” | 同时支持对话修改 | 对话应能定位正在编辑的课件及具体场景，修改后可预览 | 未证明截图中的对话与编辑器已自动双向联动 |
| 朱丹14:33“我们也要实现这种剪辑工具的支持” | 群聊明确提出支持编辑工具的方向 | 需要评估课件编辑能力进入平台的范围与承载方式 | 不等同于要求完整复刻剪映或指定必须采购某工具 |
| 两张截图 | 可见HyperFrames、素材区、预览区、图层区、时间轴、导出入口，以及对话并排展示 | 可借鉴“预览＋对象编辑＋时间控制＋对话”的工作方式 | 未实操参考工具；不能据截图确认全部按钮、接口、保存和多人协同能力 |
| 第二张截图中的对话 | 提到参考原片的结构图、图示、图片和图标动作，减少仅有文字框的呈现 | 课件应能增加解释知识点的图形和基础动画 | 截图内文字是示例修改意图，不能推导为自动复刻任意视频的要求 |

业务目标是让制作人员在AI生成后完成可控修改，并形成可审核的视频成果。核心价值为局部修改、保留人工调整、减少平台与外部工具之间的搬运；效率提升幅度需试制后测量，不预设百分比。

### 1.2 与现有范围的关系

现有共识第5节规定画布用于查看，不包含在线文档编辑或视频剪辑。本次聊天新增编辑诉求，与旧边界存在差异。本稿先作为扩展方案评审，差异登记Q26；保留双方依据，不直接将旧共识改为已支持编辑。

继承项目隔离、人工确认、资源四类型及手动入库规则。继承“员工提交、主管审核通过后任务完成并计数”；保存工程、导出成功和存入资源库均不代表主管审核通过。

## 2. 产品定位与建议范围

建议定位为“面向AI生成课件的轻量编辑工作台”，首先覆盖知识讲解类课件。输入是平台支持的可编辑工程，输出是可续做的工程版本与视频文件。

| 实现方向 | 适用性与取舍 |
|---|---|
| 内置轻量课件编辑器（推荐评审） | 将场景、文字、素材、配音和基础动画组织成工程，支持手动与AI修改；与任务、权限和版本更容易形成闭环，但需开发编辑和渲染接入 |
| 外部工具编辑后回传 | 可作为部分制作类型的过渡路径；要保留工程与成品映射，平台外编辑及计量仍有断点，不能宣称已满足站内直接编辑 |
| 完整专业剪辑平台 | 能覆盖更多特效和多轨操作，但范围大、交互与工程兼容要求高；聊天记录不足以支持将其作为首版承诺 |

以下为建议的最小闭环，全部待Q26评审，不代表正式优先级或排期。

| 建议纳入最小闭环 | 后续单独评估 |
|---|---|
| 生成工程后直接在编辑态预览；历史工程续做 | 任意第三方工程导入、任意视频自动恢复图层 |
| 场景增删、复制、排序；文字和图片编辑；简单图形、图标及基础动画 | 专业关键帧曲线、复杂特效、自由多轨剪辑、3D动画精修 |
| 配音、字幕与场景时间检查；替换项目内音视频素材 | 完整音频工作站、自动复刻参考视频、批量生成 |
| 对话局部修改、候选版本确认、撤销与保存恢复 | 多人同时编辑同一工程、移动端完整制作 |
| 固定版本导出、返回成果清单、手动入库、任务审核衔接 | 学习平台对接、互动课件发布和跨项目共享 |

普通MP4只作为一个视频素材使用，不承诺直接修改其中已合成的文字、人物、图形或背景。文档和图片的独立成果查看继续沿用原PG11规则，不扩大成通用文档编辑器。

## 3. 用户、对象与业务流程

制作人员负责本人获授权任务的课件编辑、生成、导出和提交；主管在授权项目查看交付物并审核，直接编辑工程需另有编辑权限。无任务的自主创作仍按Q19处理，不由本稿强制取消或开放。

| 对象 | 用途与关系 |
|---|---|
| 制作任务 | 工作要求、负责人和审核记录；沿用既有任务模块 |
| 创作会话 | AI对话上下文；与工程建立关联，切换工程时明确对话修改目标 |
| 课件工程 | 可编辑场景、元素、素材引用、时间及样式的集合；属于一个项目，有稳定工程标识 |
| 工程版本 | 一次可恢复的保存或已应用修改；记录操作者、来源和基于版本 |
| 导出任务 | 将一个固定工程版本转成视频的执行记录；与制作任务分别管理状态 |
| 视频成果 | 成功导出的文件，关联工程及版本，可下载、手动入库或提交审核 |

推荐流程：从制作任务进入AI协作 → 生成可编辑工程 → 在课件编辑态预览 → 手动调整或提出对话修改 → 核对修改并保存 → 确认导出 → 查看视频 → 按需入库 → 选择视频提交主管审核。退回后进入原工程继续修改，重新导出并提交新的成果版本。

生成失败停留在原会话并保留已有成果；AI修改失败保留当前工程；导出失败仅影响该导出任务。三个失败均不自动将制作任务标记为失败或完成。

## 4. 功能设计

本节为待评审的行为规则。使用E01—E08作为本专题功能定位，不替代项目R编号。

### E01 进入与续做

- 入口沿用PG11内容协作智能体。当前会话首次生成有效的可编辑工程后，画布直接进入该工程的编辑预览，不要求用户先下载再上传。
- 后台其他会话生成完成时只更新其状态和成果，不抢占用户正在操作的工程；当前工程有未保存改动时，新成果提供“打开编辑”入口，不强行替换。
- 成果清单显示工程与导出视频的关系，避免将工程误认成已导出成片。历史工程提供“继续编辑”，打开最近成功保存版本；已导出视频提供“查看视频”和可用时的“编辑源课件”。
- 没有可编辑源工程的视频仅按素材查看与使用，明确说明不能直接编辑内部图层；不提供看似可编辑但实际无效的入口。
- 进入前检查项目权限、工程归属和任务状态。加载失败可重试；源工程不存在、格式不支持和无权限分别提示可执行的处理方式，不泄露其他项目内容。

### E02 编辑工作台与预览

建议在PG11承接专门的课件编辑态，支持放大工作区并返回原会话，不另建平行任务模块。具体布局待原型评审。

| 区域 | 主要内容与行为 |
|---|---|
| 顶部 | 工程名、项目/任务、保存状态、撤销/重做、历史版本、导出及返回 |
| 左侧 | 场景列表与素材选择；切换查看当前课件结构和项目授权素材 |
| 中间 | 当前场景画布及播放预览；选择对象、缩放、适应窗口和全屏预览 |
| 右侧 | 当前对象属性与图层；显示名称、类型、可改属性、显隐和锁定 |
| 底部 | 场景顺序与时长、元素出现区间、配音/字幕定位；先满足课件时间控制 |
| 对话区 | 复用所属创作会话，显示当前工程、场景和选中对象作为修改上下文；支持收起 |

选中场景或对象后，画布、属性区、图层和对话目标同步。切换场景保留未保存编辑；切换工程前按E06处理保存。播放、暂停、拖动播放位置和调整预览音量不修改工程内容。

### E03 场景、元素与基础动画编辑

- **场景**：新增空场景、复制、删除和调整顺序。删除有内容的场景需确认并可撤销；删除后至少保留一个空场景，不允许空内容直接导出。
- **文字**：修改正文、位置、尺寸、字体、字号、颜色与对齐；提示溢出和缺失字体。可用字体采用平台实际提供的列表，思源字体的具体文件与标准继续关联Q12。
- **图片与图标**：插入、替换、移动、缩放和删除；缩放默认保持比例。替换素材尽量保留原位置、时间和动画，不能保留时明确提示变化。
- **简单图形与结构图**：支持形状、线条、基础连接关系及图标组合，用于解释知识点；最小图形清单在Q26确认。不承诺任意专业绘图功能。
- **图层**：查看层级、调整前后顺序、显隐和锁定。锁定对象不能被手动误改；AI修改也须遵守锁定范围，不能绕过。
- **动画**：从有限预设选择入场、退场或强调效果，调整开始时点和持续时间；类型清单待评审。示例为淡入、移动、重点强调，均非已确认效果库。
- **局部视频**：允许在场景内引用视频片段并设置起止位置、是否使用原声；不将该能力扩写为完整多轨剪辑。
- 文字内容、图形关系和讲解含义仍由制作人员检查，AI新增动画不能以视觉丰富为由改变业务知识。

### E04 配音、字幕与时序

- 按场景查看讲解文本及关联配音，支持播放、替换音频、调节音量和静音。具备真实TTS服务后提供“重新生成本段配音”，不把修改文本等同于音频已更新。
- 字幕文本与讲解文本分别可见。修改字幕可仅纠正显示文字；修改讲解内容后标记关联配音、字幕时间需要复核，由用户选择重新生成或继续调整。
- 调整场景时长、顺序或配音后，检查字幕、动画、音视频的有效时间区间；不得静默截掉讲解或把字幕移动到其他场景。
- 首轮建议以场景为主要时间单元，支持字幕区间和素材片段时间调整。跨场景连续背景音乐、自动重排策略及细粒度时间轴能力待Q26确认。
- 素材起止范围非法、元素超出场景或引用缺失属于阻断问题；配音与字幕语义不一致、文字溢出等可判断问题提示人工核对。无法自动识别的质量问题不能显示为已检查通过。

### E05 通过对话修改同一工程

- 用户可针对整份课件、某一场景或选中对象提出要求，例如“把当前标题改短”“替换这一张图”“给流程图增加逐步出现动画”。提交前显示目标范围，指代不清时请求补充，不擅改整份课件。
- AI读取当前已保存版本和本次目标；有未保存手动修改时先保存成功再执行。只使用当前项目获授权资源、可用技能及实际接入工具，外部素材来源按平台既有规则处理。
- AI结果先生成候选修改，展示影响场景、修改摘要和预览，由用户应用或放弃。应用前不覆盖当前工程；应用成功形成新版本，放弃保留原工程。
- 候选应用前检查工程结构、素材权限和基础预览；不合法或无法加载的结果标记失败，不允许作为正常候选覆盖工程。预览成功不替代用户对知识准确性和视觉效果的判断。
- AI执行期间可查看、播放和编辑其他工程；建议同一工程暂时禁止新的写入，避免人工与AI互相覆盖。取消请求后，迟到结果不得自动应用。
- 应用时再次比对基础版本。其他标签页或设备已更新工程时，提示版本冲突，允许加载最新版后重新提出修改；不直接覆盖，不承诺首轮自动合并。
- 需要更改锁定对象或扩大修改范围时先说明并请求用户确认。失败说明原因，保留原工程、要求及可重试入口；不得把失败输出标成已应用。

### E06 保存、版本与恢复

- 区分“有未保存修改、保存中、已保存、保存失败”，提供手动保存并建议自动保存；自动保存间隔待技术验证，不用仅写入浏览器缓存冒充持久保存。
- 保存成功后重新打开能恢复场景、素材引用、配音、字幕、时间和样式。素材引用需固定可追溯版本，资源库更新或删除不能无提示地改变已有课件；保留依赖还是阻止删除由Q27确定。
- 支持当前编辑操作撤销/重做；历史版本记录操作者、时间、变更来源和摘要。恢复旧版本形成新的当前版本，不删除后续历史或既有审核依据。
- 保存失败保留当前可恢复内容并允许重试。离开、关闭或切换工程前提示未保存状态；不能保证断电前未同步内容全部恢复，恢复能力需在实际环境验证。
- 首轮建议一个工程同一时刻只有一个写入会话，其他打开者可只读查看。异常退出的占用释放、超时与接管策略待Q27；服务端仍需版本校验，不能只禁用页面按钮。

### E07 确认与导出视频

- 点击“导出视频”先保存，并检查有效场景、素材可访问性、字体、时间范围及工程可渲染性。阻断项给出对应场景和处理入口；允许导出的提醒项明确展示。
- 确认面板展示课件名、工程版本、时长和可用导出参数。建议首轮交付MP4，画面比例、分辨率、帧率、字幕方式及编码兼容要求见Q28，不硬编码为业务已确认标准。
- 用户确认后创建独立导出任务并固定工程及素材版本。状态为排队中、导出中、成功、失败；进度仅在可获得真实数据时显示百分比，否则展示实际阶段。
- 用户可离开页面并在原成果清单查看结果。同一请求重复点击或重复回调不生成重复有效成果；重试明确使用原导出版本还是另行导出最新版本。
- 导出期间继续编辑生成新工程版本，不能影响正在导出的版本。完成时注明导出版本；若已有更新，提示“课件已更新，当前视频对应较早版本”。
- 成功需实际文件可访问、可播放且有完整元信息，不以渲染进程结束代替成功。失败保留工程和之前成功视频，显示原因及重试入口。
- 导出成果可下载、预览，并沿用现有手动保存到项目视频资源库的流程；不默认入库，不新增“工程”作为第五类资源。

### E08 任务审核与计量衔接

- 员工选择导出成功的视频版本提交审核，记录任务、工程版本、视频、提交人及说明；缺失视频或导出失败不可提交为视频交付。
- “确认导出”是制作人员对输出版本的确认；“审核通过”是主管对任务交付的批准，两个动作、操作者与状态分开。
- 待审核成果固定为提交快照。后续编辑、导出或资源库更新不替换审核对象；退回后保留意见并续做源工程，重新提交新视频版本。
- 同一课件反复保存、生成和导出不直接增加成品数量；审核通过后的去重、重开与修订规则沿用Q20，不在本稿另建计数算法。
- 编辑活动归属当前任务及实际操作者；AI调用记录真实用量，渲染排队/执行另计，不把渲染耗时当作人工编辑时长或Token。关闭编辑器不停止已发起后台任务的归账；具体计时阈值沿用Q21。

## 5. 权限、数据与异常规则

| 情况 | 建议行为 |
|---|---|
| 员工访问他人任务工程或其他项目工程 | 按既有任务及项目权限拒绝；列表、直达链接、素材、历史版本、导出和下载一并校验 |
| 主管查看待审核内容 | 打开提交时的固定视频与版本信息；不因审核权限自动获得工程编辑权 |
| 任务归档、账号停用或权限撤回 | 阻止新的写入、导出和提交；历史与已产生费用证据保留；后台在途任务的取消/收尾规则待Q27 |
| 素材缺失、格式不支持、字体不可用 | 定位问题及影响场景；允许替换、恢复或选用支持格式，不静默用占位图导出成片 |
| 断网、刷新、重复请求 | 保留已成功版本，区分本地未同步内容；保存、AI应用和导出均防重复，重连后核对实际状态 |
| 版本冲突或AI结果迟到 | 保留当前版本，不自动覆盖或切换；告知差异和下一步 |
| 数据采集失败或服务未返回用量 | 标记缺失/待补，不显示为零，不丢弃失败执行的实际消耗 |

工程至少记录项目、任务关联（如有）、来源会话、创建人与编辑人、当前版本、场景和元素标识、素材版本引用及更新时间。执行记录保留发起者、输入版本、输出版本、状态和实际用量，便于追溯一次修改或导出。

工程及AI生成内容在受控执行环境中预览和渲染，不允许读取其他项目文件或平台凭据；保存与访问由服务端校验权限。以上是平台隔离的实现约束，不要求新增面向用户的技术配置页面。

## 6. 可实施性与依赖

必须具备可编辑工程生成、工程存储、编辑组件、AI修改执行和视频渲染能力；仅上传技能包或嵌入播放器不能实现本需求。

建议先建立“平台工程格式—编辑器—AI执行—渲染”的一致输入输出约定。HyperFrames可作为候选工具核验，不绑定为最终选型；工具可用性不等于账号权限、项目隔离、任务审核和版本衔接已具备。

评估候选工具时核对：工程读写和稳定元素标识、支持的编辑属性、中文字体与音画同步、预览/导出一致性、部署和授权条件、资源依赖、失败恢复、升级兼容，以及与项目权限/存储的衔接。具体服务、部署架构、预算与工期由研发验证后提出，不从参考截图推算。

建议先用一份真实知识讲解课件试制：生成 → 手动改字和换图 → 对话增加图形动画 → 保存重开 → 导出 → 提交固定版本。此试制是排期前的验证建议，不是已安排研发任务。

性能验收需先确定典型/最大课件时长、场景及元素数量、素材大小、并发人数、目标浏览器和设备，再约定打开、编辑响应、预览和导出指标（Q28）；不得用无依据的秒数保证效果。
