# 数据统计模块：大模型用量、调用量与费用需求

版本：v0.2｜日期：2026-10-23｜状态：需求草稿，待业务与研发评审｜页面承接：PG20 数据统计

## 1. 目标、依据与确认状态

本模块回答三个问题：**谁、在哪个项目使用了多少模型用量；调用了哪些平台和模型、多少次；产生多少费用，账单与估算有何差异。** 支持成员自查、项目管理员管理项目消耗，以及获授权的跨项目管理人员核对平台支出。统计值是费用与使用证据，不自动构成员工绩效评分。

| 事项 | 当前状态与依据 |
|---|---|
| 按人员、项目统计 Token、各平台模型调用费、调用量 | 用户 2026-10-23 明确提出。本稿将“平台”解释为模型服务供应平台，另保留平台内模型维度。 |
| 同时展示账单费用和估算费用 | 用户 2026-10-23 明确选择，记 D080。两种金额必须分列、标识来源，不相互替代。 |
| 每日 Token 人员堆叠柱状图 | 用户 2026-10-23 明确要求，记 D081。每天一根柱，按实际调用人分段，展示每日总量及每个人的用量。 |
| 调用与 Token 的原有计量原则 | 继承[协作任务、数据看板与权限需求说明](../03_功能设计/协作任务、数据看板与权限-需求说明.md)第 4—5 节：唯一调用、实际操作者、任务/会话归因、重试和迟到回调、缺失用量处理。 |
| 项目内权限与跨项目范围 | 当前项目成员看本人、项目管理员看本项目的方向已有设计依据；跨项目统计与导出仍按 Q22 评审。本稿的跨项目角色授权是建议方案。 |
| 服务、价格和实际账单接口 | 供应平台/模型清单、真实接入及价格来源尚需核验（Q10—Q12/Q33、Q41）。原型中的模型名、数据和费用不作为实际计费依据。 |

项目规则所指的业务共识主本原路径当前缺失，沿 Q35 跟踪；本稿不以较早的 `-v2` 文件代替已确认主本，也不宣称现有系统已经采集或计费。

## 2. 范围与页面结构

数据统计入口沿用 PG20。原有“成员任务统计与审核分项”保持独立视图；本次增加“模型用量与费用”视图，不把任务完成率与模型费用混成一个指标。统计范围包括平台发出的文本、图片、音频、视频等模型请求，以及同一用户动作触发的多次实际模型请求。没有调用外部模型的纯本地编辑、资源浏览、确定性工具执行，不进入模型调用量。

建议页面由五层构成：

1. **总览**：筛选期间的总调用量、成功/失败调用量、输入/输出/总 Token、账单费用、估算费用、两者差异、未出账/缺失计量的调用数及最后更新时间。金额按币种展示；跨币种总计仅在具备已记录汇率时出现。
2. **每日 Token 人员堆叠柱状图**：横轴为日期，每天一根柱；纵轴为已取得的总 Token 数，同日各人员用量堆叠成当天柱高。图表细则见第 3.4 节。
3. **按项目、按人员汇总**：切换“项目视图 / 人员视图”，项目可展开人员，人员可展开项目；同一人的跨项目汇总只覆盖当前有权查看的项目，并明确范围。每行保留平台和模型下钻。
4. **平台与模型分析**：以供应平台→模型为层级，展示调用数、Token 或原生计费量、账单费用、估算费用、差异及费用状态；可与项目、人员筛选交叉。
5. **调用明细**：查看每次实际请求的调用时间、项目、发起人、任务/会话、平台、模型、状态、用量、原币费用、账单/估算来源和补报记录。权限范围内允许按调用 ID 查询；不在统计页面暴露提示词正文、敏感文件内容或密钥。

筛选建议：时间范围、项目、人员、平台、模型、调用状态、费用状态；项目/人员筛选受权限约束。时间默认展示最近 30 天可作为交互建议，具体默认值待原型评审。时间边界统一为 Asia/Shanghai，自定义区间采用“起始时刻含、结束时刻不含”，避免相邻区间重叠。

## 3. 统计对象与归因

### 3.1 记录粒度

**一条调用记录 = 一次已向模型供应平台实际发出的请求或作业。** 每条记录具有平台内唯一的调用标识；供应平台返回的请求/作业 ID 单独保存，跨平台不能仅用供应商 ID 去重。一次用户发送或技能执行可能调用意图识别模型、文本模型和生图模型，应产生多条实际调用记录，并用同一个业务执行 ID 关联。平台请求未发出时记内部执行失败，不计模型调用量。平台已接收但失败的请求计入总调用量，若实际产生用量或账单费用仍计入相应消耗；成功调用量和失败调用量分列。每次真实重试分别计数，重复回调不得重复计数。

调用创建时固化发起人、项目、任务、会话、平台、模型、请求时间；后台回调按发起记录归因，不按回调时当前页面或当前任务负责人归因。改派、成员离职或项目归档不重分历史调用。由用户发起的异步任务归发起用户；确属系统定时/自动任务且没有个人发起人时记“系统调用”行并归所属项目，不摊派给成员。无法确定项目或发起人的记录进入“待归因”异常队列，不能悄悄归入某个人。

### 3.2 核心指标口径

| 指标 | 计算与显示规则 |
|---|---|
| 总调用量 | 去重后的实际平台请求数，含成功、失败及排队后被平台接收的请求；成功量、失败量单列。未知最终状态暂列“处理中”，不预设成功。 |
| 输入/输出/总 Token | 优先取平台回传的对应实际值。平台无总量但完整返回输入和输出时，可标明“分项求和”；只返回部分字段则总量“未提供”。缓存、推理等子项按平台语义单列，不再叠加到已含这些部分的总量。 |
| 非 Token 用量 | 图片张数/尺寸、音视频秒数、生成作业数等按供应商原生计费单位记录；没有 Token 回传时显示“未提供”，不得填 0、换算虚构 Token 或跨单位相加。 |
| 账单费用 | 供应平台计费记录或账单明细能够匹配至调用时，展示该平台原币金额、币种、账期、账单来源与状态；真实退款/补扣按供应平台证据调整，保留历史。账期合计无法可靠分配到单次调用时，只在平台/账期层显示，不虚分到人员或项目。 |
| 估算费用 | 按该次调用的计费量、适用价格版本、币种与计费规则计算，标“估算”。原生计费量或有效价格缺失时显示“不可估算”，不得用 0 代替。可能存在阶梯价、缓存价、包量/折扣、税费等差异，不承诺等于账单。 |
| 费用差异 | 仅对同币种、同计费范围、已能逐调用匹配且两种金额均具备的记录计算“账单－估算”；无法一一对应时只显示可核对层级的差异，并提示不可比原因。 |

金额按原币和供应平台计费精度保存；页面四舍五入只影响显示，汇总用原始精度计算。不同币种不直接相加。若业务需要统一币种汇总，应记录汇率来源、币种、汇率值和适用日期，页面展示折算币种及汇率版本；该配置和账单抵扣/税费处理待 Q41 评审。

### 3.3 时间与聚合

用量和估算费用按**平台实际请求发起时间**归属统计期间；异步作业也按首次提交到供应平台的时间计入调用量，其最终用量和费用在结果返回后回补原期间。账单费用同时提供“调用发生期间”和“平台出账账期”两种视角，页面必须显示当前视角；前者只汇总可匹配到调用的账单，后者可展示无法下钻的账期总额。迟到回调、账单补录和冲正重算受影响历史期间，保留修订时间及前后值。

项目合计 = 授权范围内该项目唯一调用之和；人员合计 = 授权范围内该人员唯一调用之和。同一人跨多个项目按调用发生时固化的项目分别展示；一次调用在“项目→人员”和“人员→项目”两种导航里出现，但全局总计只计一次。模型切换、多技能串联和失败重试均按真实请求数归集，不把一条调用的全部消耗重复分配给多个技能。

### 3.4 每日 Token 人员堆叠柱状图

- **数据口径**：先应用页面的时间、项目、平台、模型等筛选及当前用户的数据权限，再按 Asia/Shanghai 的调用发起日期、调用时固化的实际发起人 ID 分组，将去重后调用的已知总 Token 相加。同名成员按不同账号分别统计；改名不拆成两人。一天所有人员分段之和加上“系统调用”“待归因”分段，等于该日图表所示的**已知 Token 合计**。人员筛选后，柱高相应变为所选人员的用量，不再显示全项目总量。
- **图形表达**：每个自然日固定一根柱；每个人固定一种图例颜色，跨日期保持一致。纵轴单位为 Token，显示时可缩写为万/百万，悬停和明细显示原始整数。日期范围内无调用的日期保留 0 基线；当天有调用但 Token 全部缺失时显示“用量未提供”标记，不绘制误导性的 0 用量柱。图下明确写“柱高仅含已取得 Token 的调用”。不返回 Token 的图片、音频、视频模型调用不纳入柱高，但在当日缺失数量中保留。
- **交互**：悬停分段显示日期、人员、该人当天总 Token、占当日已知合计比例、输入/输出 Token（仅在完整可得时展示）及该人用量缺失调用数；悬停柱顶显示当日已知合计与缺失调用总数。点击人员分段，下方汇总与调用明细定位到该日期和人员；点击日期柱顶定位到该日全部有权查看的调用。图例支持按姓名搜索、单人高亮及取消高亮；点击“系统调用”或“待归因”分段查看对应异常明细。
- **拥挤情况**：人员过多时图例可滚动/搜索，颜色与姓名始终能对应；可将低用量人员在画布上视觉合并为“其他人员”，但点击后必须展开具体人员和各自准确数值，不能丢失成员数据。日期较多时提供横向浏览或范围缩放，仍保持逐日粒度，不自动改按周/月汇总。
- **更新与校验**：异步回调按原调用日期补入对应柱；修订后重算图表、总览与明细并更新时间。同一筛选下，每日柱高之和等于总览的已知 Token 总量；各人分段之和等于人员表对应期间的 Token，总量之外另列未提供 Token 的调用数。图表导出如需实现，应带筛选范围、时区、口径和缺失数量，不仅导出图片。

## 4. 权限与操作

项目成员可查看本人在当前有权访问项目中的调用明细与汇总。项目管理员可查看其管理项目的全部人员、平台和模型明细。跨项目总览建议仅授予显式配置的经营/费用管理权限，并只覆盖其获授权项目；系统管理员身份本身不默认获得业务统计数据。成员退出项目后的本人历史可见范围、跨项目角色和导出权限沿 Q22 确认。所有筛选、明细、导出接口执行同一服务端数据权限校验；不能通过传项目 ID 或调用 ID 越权访问。

具备数据导出权限的人员可导出当前筛选结果，导出列包含口径、统计时区、生成时间、权限范围、费用来源与币种，明细中不导出提示词正文或资源内容。价格维护、账单接入、人工匹配与费用修订应由专门授权角色操作，保留操作人、时间、理由和前后值；普通项目成员不得改动计量数据。

## 5. 数据采集、对账与异常

1. 模型网关/调用服务在请求时写入业务执行 ID、唯一调用 ID、归因快照与模型标识；结果/回调补齐状态和原生用量。多次结果、重放、超时后补到须幂等。
2. 建立供应平台与模型目录：稳定标识、显示名称、计费单位、可返回的用量字段、价格版本及生效时间。不同平台相同模型名不能混为一个模型；别名变更不得抹掉历史标识。
3. 估算费用按调用时间命中的价格版本计算，并保留价格来源、计价公式和输入量快照。没有有效版本时提示“价格缺失”。任何事后价格修订都留下版本；是否追溯重算由费用管理员明确执行并留痕。
4. 账单接入后优先用平台请求 ID/作业 ID 对应调用。对不上、重复、跨账期、聚合账单、退款或补扣进入待对账明细；不得把平台账单总额平均摊给项目或人员。展示“已匹配/待出账/无法匹配/已调整”状态及对应金额、数量。
5. 接口未返回 Token、作业未结束、价格缺失、账单延迟、币种不一致、归因缺失应分别标识。总览显示这些不完整记录的数量和未覆盖金额，避免“看上去准确”的总数误导判断。
6. 保留原始计量字段与供应平台响应/账单引用、更新时间、修订轨迹；敏感信息脱敏并按权限查看。数据保留周期与账单可追溯期限待安全和财务制度确认，不在本稿编造年限。

## 6. 建议验收场景

1. 同一成员在两个项目各调用一次，项目汇总分别计数，人员跨项目汇总为两次，平台总计仍为两次；无跨项目权限者只见授权项目。
2. 一次会话触发文本和图片两个平台请求，调用量为 2；图片平台未提供 Token 时总览显示“1 条 Token 缺失”，不将该条当作 0 Token。
3. 平台已接受的失败调用返回用量和费用：总调用量与失败量各加 1，实际用量/账单费用进入汇总；平台前拦截失败则不计模型调用量。
4. 同一请求重试两次且第二次成功：真实两次请求各计数；任一次重复回调只保留一条；任务改派后原调用仍属于原发起人。
5. 价格版本发生变化：前后调用分别命中各自有效价，估算费用可复算；账单未回时标“待出账”，两种费用列不互相填充。
6. 已出账明细可逐调用匹配时显示账单、估算与差异；只有平台月度总账时，平台账期可见，人员/项目账单费用显示“无法分摊”，不能假装精确。
7. 异步调用在 9 月发起、10 月结束并出账：期间用量与可匹配账单回补 9 月调用期间；账单账期视图按平台账期显示；两处数字及最后修订时间可追溯。
8. 未授权项目成员通过直接调用明细或导出接口访问其他项目，服务端拒绝；有权用户导出数值、币种、筛选范围与页面一致。
9. 两人同日分别消耗 600 和 400 Token：该日一根堆叠柱高 1,000，两个分段分别为 600/400；按其中一人筛选后柱高变为对应数值，点击分段能下钻其当日调用。
10. 某日仅有未返回 Token 的图片模型调用：当日保留“用量未提供”提示和缺失调用数，不画 0 用量柱；迟到回调补到后，该日柱高、人员表与总览同时更新，三处数字一致。

## 7. 待评审问题与实施依赖

- **Q22**：跨项目统计角色、成员离开项目后的历史可见性及导出授权。建议显式授权，不从“系统管理员”身份自动推断。
- **Q41**：可接入哪些供应平台的逐调用账单，何时出账；聚合费用、优惠/税费、退款、跨币种汇率和费用差异的对账层级。影响“账单费用”可细化到人员/项目的范围。
- **Q42**：正式平台/模型清单、有效价格及历史版本从何取得，由谁维护与审核；图像/音视频的计费量字段、包量规则及更新频率。影响估算费用准确性。
- **Q43**：模型网关能否稳定提供请求 ID、发起人和项目快照；已有历史调用/账单能否补采、从哪一日期开始统计。影响数据完整性和上线迁移。

建议评审顺序：先确认模型调用埋点与费用来源，再确认权限和页面；完成接口与账单样本核验后，方可定正式交付范围、排期与财务口径。本稿未创建原型、禅道需求或真实计费接口。
