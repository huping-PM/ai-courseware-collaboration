## 1. 背景与依据

来源为用户提供的[S20原始需求截图](../01_业务资料/外部材料/2026-09-28-AI协作智能体任务处理记录/原始需求截图.png)，截图中的沟通依次提出：

> 我们先把那个大模型处理任务的过程记录给完整展示吧，支持展开和缩放，尤其是大模型处理这个任务时调用了哪个技能，没有这个过程，不方便调试
>
> 嗯，现在已经完整展示了，只是没有留下历史记录
>
> 所以我们要加一个历史记录功能，在思考过程中展示过程记录，思考完后就自动缩放，只显示最终输出结果，但是点击又可以展开查看思考过程

据此，本次核心诉求是**保留任务处理过程的历史记录，处理时展示，完成后自动收起，需要时重新展开查看，尤其能查到实际调用的技能**，便于回溯和调试。

“现在已经完整展示”仅为截图中的沟通反馈，本次未实测系统，不据此认定现有展示或存储能力已实现。截图中的“缩放”按上下文解释为过程区域的收起/展开，不涉及画布比例缩放；“思考过程”在本文指实际可观测的执行步骤、技能调用及可用过程摘要，不要求展示模型内部隐藏推理，也不补造未被记录的过程。

相关上下文沿用[PG11需求说明](../03_功能设计/内容协作智能体-需求说明.md)中的项目隔离、会话切换与任务归属，以及[需求梳理R08](AI课件协作平台-项目需求梳理.md)。根规则指定的无版本后缀共识主本当前缺失；已只读查看[现存共识文件](AI课件协作平台-业务流程与需求共识-v2.md)，其正文标注v0.36，未将其自行认定为替代主本或据此覆盖后续规则。

## 2. 使用场景与范围

用户在AI协作智能体中发起一次处理请求时，查看当前执行进展；处理完成后优先阅读最终输出，需要排查问题时展开对应过程；离开后重新进入原会话，仍能查看已保留的过程记录。

这里的“任务处理”指会话内一次请求对应的处理过程。同一会话多次请求应能区分各自过程与输出，不将多轮记录混为一条。本次只补充PG11中的过程展示和历史留存，不扩展管理任务的分配、审核、完成判定或统计规则。

## 3. 核心规则（按截图诉求整理，待评审）

| 场景 | 需求规则 |
|---|---|
| 处理中 | 在对应请求的过程区域展示已产生的可观测处理记录，按实际发生顺序持续更新；默认展开，用户可手动收起或展开。尚未产生的步骤不提前显示为已执行。 |
| 技能调用 | 能查看本次实际调用了哪个技能，并与对应执行步骤关联。界面显示的技能调用须有实际调用记录支撑，不能把草稿中选择的技能、可用技能列表或计划调用视为已调用。 |
| 处理完成 | 最终输出就绪后，自动收起该次过程正文，保留最终输出和可点击的过程查看入口。“完成”指本次AI请求处理完成，不表示管理任务审核通过。 |
| 再次展开 | 点击入口展开该次已保存的过程记录，再次点击可收起；展开/收起只改变显示状态，不删除记录、不重新运行请求、不改变最终输出。 |
| 历史留存 | 过程记录随所属项目、会话及对应请求留存。刷新页面、切换会话后返回，或重新进入历史会话，仍可展开查看已有记录；不能只依赖当前页面临时显示。具体保留期限见Q34。 |
| 多轮与隔离 | 各次请求的记录与对应输出关联，切换会话或项目时不串入其他任务记录。查看沿用原会话的访问权限，本功能不扩大可见范围。 |

记录范围以真实可获得的执行数据为准。为支持最小调试需要，建议每个步骤展示步骤名称/摘要，技能调用展示技能名称；执行状态、时间和失败说明在实际可获得时一并保留。以上字段为AI建议，需与实际过程数据核对，不预设完整调用参数或技术日志均可取得。

## 4. 建议异常边界与待确认

以下为AI建议，尚非已确认业务规则；统一归入Q34，不阻碍先评审正常完成后的留存与展开流程。

| 未决事项 | 建议处理 | 影响 |
|---|---|---|
| 保留期限与删除联动 | 明确记录保留多久，以及会话/任务删除、归档时是否保留或同步删除；未确认前不承诺永久保存。 | 历史可查范围、存储与生命周期。 |
| 失败、取消及重试 | 失败或取消时保留已有过程及实际结束状态，建议默认展开便于排查；重试建议另记一次处理过程并保留原记录。具体默认折叠规则待确认。 | 异常回溯及多次尝试的区分。 |
| 旧任务无记录 | 建议提示“该次处理暂无历史过程记录”，保留原最终输出，不倒推或伪造历史步骤。 | 历史数据兼容及用户预期。 |

另外，记录暂时加载失败时建议显示加载失败及重试入口，保留最终输出，不把“加载失败”当作“从未产生记录”；实际记录字段和完整性需在功能设计、接口核对时验证。

## 5. 验收标准（草稿）

1. 发起一次处理请求，过程中可见已产生的执行记录；收起再展开仍能查看，步骤顺序与实际记录一致。
2. 对一次实际调用技能的请求，记录能够指认调用的技能；仅选择但未调用的技能不显示为“已调用”。
3. 请求正常完成后，过程正文自动收起，最终输出保持展示，过程查看入口可用；展开后可回看该次已有记录。
4. 在同一会话连续发起两次请求，分别展开时，只展示各自的处理记录，并能对应各自最终输出。
5. 对保留范围内的新记录，刷新页面、切换会话再返回、重新进入历史会话后均可查看；展开操作不触发再次生成。
6. 不同项目和会话的记录不串入，原本无权查看会话的用户不会因过程入口获得额外访问权限。
7. 失败/取消/重试、旧任务无记录及删除后的验收预期，在Q34确认后补齐；不以本文建议当作已批准规则。
