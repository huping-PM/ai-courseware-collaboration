# AI课件协作平台：产品开发计划

日期：2026-09-14。版本：v0.1。状态：建议计划，待范围评审与研发估算；未排期、未分配具体负责人，不代表已启动开发。

## 1. 建设建议与计划依据

建议首版采用“复用项目与资源基础、新增制作任务和工作台、共享技能支撑生成”的方式。先完成一条真实课件从课题、脚本到视频审核和保存的闭环；情景动画允许外部制作过渡的前提是业务确认且输入输出能够回到任务内。

按当前推荐承载方式，页面改动分为：

- **修改4处已有页面：** 项目列表、项目基本信息、图片资源、文件资源。另调整项目内导航入口。
- **新增3个主要页面：** 制作任务列表、技能管理、课件制作工作台。
- **新增嵌入界面：** 技能详情/编辑、模板选用与样例、工作台内6类视图，以及必要选择、确认、失败与回传弹窗；不重复算作独立页面。
- **优先复用2处：** 登录、成员管理。先核验认证与权限；发现具体缺口再估算修改，不安排无依据的重做。
- **配置先行：** 模型接入能力需要建设，独立模型管理页面先不作为首版前提。
- **条件范围：** 系列目录与进度保留规划，是否首版纳入由Q08/Q09确认。

以上是本次建议方案，既有12个PG容器仍保留在功能清单中；“4处修改＋3个新页”按实际建议承载计数，不表示其余业务能力被删除。

## 2. 哪些页面修改，改什么

下表“保留”指建议优先复用，不表示已经验证可用。页面名称沿用实页记录；改动按功能差异列出。

| 已有页面/位置 | 对应清单 | 保留部分 | 本次拟调整 | 验证结果/依赖 |
|---|---|---|---|---|
| 项目列表 | PG02；F004—F007 | 项目卡片、已有筛选/视图、创建及设置入口 | 增加明确的制作任务进入路径；进入后保持所选项目上下文 | 从一个项目进入其任务，不能串到另一个项目；Q01/Q04 |
| 项目设置·基本信息 | PG03；F008—F011 | 原基本信息和封面表单 | 增加或承接项目共同受众、目标、背景，以及关联资料/默认制作依据；优先允许文档引用，避免增加大量重复字段 | 新任务能继承并查看依据；背景更新不静默覆盖在制内容；Q02/Q04/Q05 |
| 图片资源 | PG07；F027—F033 | 分类、查询、缩略图/元数据列表、上传布局 | 增加选入制作任务/当前生成请求；补所属项目、用途及成果关联；角色/场景图使用可复用选择器 | 图像被真正带入请求，确认所用对象可回看；Q01/Q07 |
| 文件资源集 | PG07；F027—F033 | 文件分类、列表及现有上传结构 | 承接文档、音视频等实际所需类型的查看/下载/引用；生成文件和外部回传文件归入正确任务/阶段 | 格式支持先核验；已有音视频能力可用则复用，只补缺口；Q07/Q11 |
| 项目内导航与共享选择入口 | 跨PG02/PG05/PG07/PG08/PG11 | 原有系统外壳与其他业务入口 | 增加制作任务、技能管理入口；公共/项目资源在选择时明确范围；维持当前项目及返回路径 | 不把制作入口覆盖为原课程列表唯一入口；未授权资源不可因切换范围暴露；Q04 |

图片与文件页共用的上传、引用、归属和公共范围能力只实现一套，不按两个页面重复建设。同一PG07在实际系统可能对应两页，故“4处修改”不是4个PG编号。

- PG06系列目录与进度：条件增补包，保留需求但不默认进入建议首版。不能因延后页面而取消旧共识中的系列能力方向。
- PG10模板页：首版合并承载选用/样例；后续业务维护量增大再拆页。

## 4. 建议首版的可交付边界

建议以一个实际组合课件作为验证对象，完整经历：选择项目 → 新建课题 → 引用资料与规则 → 生成/修改/确认脚本 → 情景及知识讲解片段 → 配音字幕与合成 → 人工审核 → 项目内保存与交付。

| 能力 | 建议首版交付方式 | 必须核对 |
|---|---|---|
| 项目/成员/资源基础 | 核验现有后复用，只做明确增量 | 不仅看页面，还要核验数据归属、真实上传/引用和权限；Q01/Q04 |
| 文本与知识讲解 | 平台内能执行经业务认可的方法，至少产出可播放讲解片段 | 不是只生成文稿或静态PPT；准确模型、技能、格式和样片标准见Q02/Q10/Q12 |
| 情景动画 | 基线建议允许外部工具制作，平台负责输入引用、分镜承接及片段回传 | 必须由Q11确认过渡可接受；原生生成若要求首版交付则增加09范围 |
| 字幕与最终合成 | 优先接入确定可用的工具；如采用外部处理，明确输入/回传并纳入真实验收 | 外部处理不能只有链接；Q03/Q11确定何处处理声音字幕以及谁完成合成 |
| 人工确认和返工 | 工作台能识别有效成果，能反馈、重试或回到相关环节 | “保存”与“确认后发起生成”不可混淆；Q05 |
| 技能和模板 | 规则可维护、样例可查看、制作时可引用 | 先支持最小内容维护，不预设审批/推荐系统；Q06 |

如知识讲解、声音字幕或合成仍只能展示模拟结果，则只能交付交互演示，不能记为生产可用1.0。外部过渡也不免除成片质量和交付责任。

### 可以并行的工作与接口条件

## 8. 验收与范围收缩原则

验收应至少包含以下真实场景；具体质量阈值由业务提供，不编造分辨率、时长、并发或成本指标。

| 场景 | 需取得的证据 |
|---|---|
| 项目与任务正确 | 参与者进入正确项目，找到任务，资源与成果无错归属；实际权限行为符合已确认范围 |
| 文字确认可续做 | 生成并修改脚本，确认后下游引用的是该成果；离开再进能找回 |
| 完整视频可交付 | 组合视频按已确认路线形成，知识文字、角色、音画字幕符合认可样片及具体规则 |
| 外部过渡闭环 | 输入明确，外部片段回传到对应任务，能继续合成和审核，不能只记录已打开工具 |
| 失败/返工 | 至少验证一次生成失败和一次内容修改；原有效成果仍可用，重做范围可判断 |
| 规则复用 | 另一参与者可使用共享技能；一次规则更新的适用范围明确，不静默替换在制成果 |
| 原系统回归 | 项目、成员、资源和原课程入口仍按已有可用行为工作；本次改动不改变原课程业务含义 |
| 最终确认与交付一致 | 已确认成片和实际下载/交付文件对应，能回查必要制作依据 |

若估算超过本迭代可用投入，先讨论减少**独立管理页面和交互复杂度**：PG09用抽屉、PG10合并选择、PG12配置先行，系列和原生情景按条件另议。不能未经业务确认删掉声音字幕、合成、人工确认、失败恢复或交付，使“首版”只剩能聊天的外壳。
