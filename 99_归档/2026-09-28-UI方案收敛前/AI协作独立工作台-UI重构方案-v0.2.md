## 1. 推荐与设计依据

**本轮依据D054，以 B「灵感工作室」继续深化，采用紧凑任务列表和分类成果条。** 下述A推荐为首次三方向对比时的设计判断，不再作为当前预览默认方向： 本项目包含资料理解、文稿起草、Markdown修改、经验沉淀和生成后审阅，持续阅读与可编辑文稿需要稳定空间。A 的常驻导航、会话与对话／文稿并排更容易承接这些工作。B「灵感工作室」更适合素材选择、封面和视频画面比较，可作为视觉生产取向的完整备选；C「专业协作舱」适合高频跨资料、配置与成果的熟练用户，信息密度和初次学习成本更高。本推荐没有量化评分或用户测试结论，最终方向由评审决定。

本次由旧系统右上【AI协作】进入独立全屏工作台；整体布局、导航与视觉可以重新设计。此项用户明确新方向优先于旧 I01 中“沿用现有系统视觉规范、不重建导航”的约束。I02—I08 已确认的文档、技能、媒体生成、任务及权限规则继续作为设计输入；本稿不因更换外壳改变其业务含义。

已读取迭代需求v0.3、迭代功能设计v0.1及国内外竞品证据。目录所引用的旧业务共识主本路径当前缺失，不能声称已读取最新版；较早v2也不作为当前共识替代品。本次可继续基于迭代v0.3和用户新方向形成可评审方案，正式同步受影响共识前仍需找回或确认主本。

竞品输入为14产品、26个去重有效官方来源，主要是官方文字与图注，没有登录后实测、逐像素视觉核验或真实模型质量对比。竞品提供区域关系和交互启发；以下色板、尺寸、模块映射是针对本项目的设计建议。

## 2. 统一入口与信息架构

### 2.1 从旧系统进入

旧系统右上保留文字清楚的【AI协作】入口，建议在**新浏览器页签**打开占满该页签内容区的独立工作台；“全屏”指独立页面，不自动触发浏览器全屏权限。原页保留原位置，方便回看任务。工作台常驻“当前项目”和“返回原系统”；从任务进入时另有“返回任务”。

入口携带当前项目；来自任务则附任务和要求版本上下文。服务端重新核验登录、项目成员关系、对象归属及访问权，不将链接参数当作授权。没有有效项目时先选择有权项目，不默认打开上次访问但已撤权的项目。直接打开收藏链接也走相同核验。

| 情况 | 建议界面与后续动作 |
|---|---|
| 正常进入 | 顶部显示项目；有任务时显示任务名、要求版本及返回任务；无任务只展示项目 |
| 新页签未打开 | 原页提供明确的“打开AI协作”备用链接，用户可自行再次打开；不重复建立创作会话 |
| 登录过期 | 展示登录提示；重新登录后重新校验目标并返回有权入口；已输入但未提交文字可保留本地草稿，重新授权前不恢复受限预览 |
| 项目／对象无权或失效 | 使用不泄露对象详情的反馈；提供返回项目选择或原系统；不展示其他项目名称、缩略图、正文 |
| 操作中撤权 | 停止后续读取和写入；保留当前用户未提交文字供复制，清除受限内容展示；不得继续调用资源 |
| 返回、切项目、关页签前未保存 | 对可控页内跳转提示保存并离开／放弃／继续编辑；浏览器关闭使用可用的离开保护机制；保存失败保持草稿 |

新页签是设计建议，仍需验证旧系统登录态传递、会话失效及多标签页版本冲突。不得在URL传递访问令牌、素材正文或其他敏感内容。

### 2.2 三个核心模块

| 一级模块 | 主要对象 | 二级组织与稳定入口 |
|---|---|---|
| 内容协作智能体 | 会话、执行记录、成果版本 | 最近会话／新会话、对话、当前文稿或媒体、成果清单；有任务则显示任务上下文 |
| 资源管理 | 当前项目的原始资料与手动入库成果 | 沿用既有资源类型与分类；搜索、列表／画廊、上传、预览与详情；协作引用只是资源的一个使用方式 |
| 智能体配置 | 技能、提示词及可用能力信息 | 技能管理／提示词管理；技能作用域、状态、版本与来源；试聊只验证草稿，不自动发布 |

项目切换、用户与权限信息、返回原系统属于外壳公共能力。任务管理及审核沿用 PG19 的业务入口与规则，通过上下文条／“我的任务”辅助入口衔接，不挤入三核心模块并列为新核心模块。全局技能维护保留系统侧 PG18，项目配置展示全局项时只读；是否有维护权以既有权限为准。

### 2.3 任务、会话、成果与审核衔接

从任务详情“开始／继续创作”进入绑定任务的会话；一个会话属于一个任务，一个任务可关联多个会话。任务上下文在三个风格中位置稳定，切页后不丢失；无任务会话不得伪造任务归属。

生成成功→人工检查→显式保存文档版本／按需入库→返回任务选择固定版本→提交审核→审核通过，分别显示不同状态和动作。保存文档、保存到资源库、提交审核、审核通过不能统一写成“完成”。工作台可提供返回任务并准备提交的入口，但审核结果仍由 PG19 及对应授权流程产生。后台执行始终回到发起的项目、任务与会话，不能因用户切换页面而挂到当前任务。

## 3. 三种风格差异

三套方案都覆盖 workspace（内容协作）、resources（资源管理）、agents（智能体配置）三个主页面；加一个旧系统右上入口 host，共10个业务演示页面。统一预览页是导航交付入口，不计为额外业务页面。它们是同一业务能力的三种空间组织方式。

| 维度 | A 静谧书桌 | B 灵感工作室（本轮深化） | C 专业协作舱 |
|---|---|---|---|
| 视觉基调 | 米白、墨绿、暖灰，安静阅读 | 亮白、墨色、珊瑚，突出视觉素材 | 石墨、青绿，强调任务与工具状态 |
| 一级导航 | 窄侧栏，项目常驻 | 顶部横向三模块，释放画面横向空间 | 紧凑图标轨，悬停及当前项配文字识别 |
| 内容协作布局 | 会话列表＋对话＋文稿 | 左侧紧凑任务列表＋大视觉画布＋右侧AI＋底部可筛选成果条 | 依据／对话／成果多栏，状态并列可见 |
| 资源页面 | 阅读友好的列表及详情 | 素材画廊、缩略图与大预览 | 紧凑分类、列表、元信息并行 |
| 配置页面 | 清晰列表与规则正文，必要时展开试聊 | 能力卡与简化设置区，强调用途 | 配置与调试并排，强调草稿／生效区别 |
| 强项 | 文稿专注、项目与会话易定位 | 图片／视频比选、素材浏览 | 多上下文并查、重复配置调试 |
| 相对代价 | 同屏大量媒体比较不如B直接 | 长文稿时须切到文稿模式，顶部空间需控制 | 首次使用较复杂，窄窗必须积极折叠 |
| 宜评审的真实场景 | 资料→讲稿→Md修改→保存 | 源图→运动要求→视频结果→变体比较 | 选择依据→调用技能→调试→查看执行结果 |

不建议初版同时上线三套布局供每人自由切换，否则会扩大维护和状态验证成本。可先确定一套主框架，再吸收另一套有依据的局部模式。A可吸收B的媒体预览与素材画廊；C可作为配置页和熟练用户操作密度的参照，均需保持导航与对象术语一致。

### 3.1 基础视觉建议

下表颜色已与本轮原型样式对齐，其余为设计基线建议；正式采用仍须通过可读性与无障碍检查，不声明已测得竞品色值。

| 项目 | A | B | C |
|---|---|---|---|
| 主背景／工作面 | `#F4F3ED`／`#FCFBF7` | `#F1F2F3`／`#FFFFFF` | `#141A1E`／`#1D252A` |
| 主文字／辅助文字 | `#243C33`／`#7A8277` | `#202127`／`#83848C` | `#E2E9E7`／`#8B9B9F` |
| 强调色 | 墨绿 `#315C48` | 珊瑚 `#ED694F` | 青绿 `#73D7BA` |
| 边界与圆角 | 暖灰细线，卡片12px | 浅灰细线，卡片16px | 深灰细线，卡片8px |
| 常用间距 | 8／12／16／24／32px | 8／16／24／32px | 4／8／12／16／24px |
| 控件建议高度 | 常规36—40px | 常规40px | 常规32—36px |

中文字体优先系统可用的苹方／微软雅黑／Noto Sans SC及sans-serif回退，避免依赖远程字体。正文建议14—15px，长文稿16px及约1.7倍行高；辅助文字不低于12px。页面标题24—28px，层级标题16—18px，Markdown源码使用等宽字体并保留中文回退。C的紧凑只减少留白，不压缩正文到难以阅读。

所有方案的成功、失败、生成中、待确认均配文字或图标，不仅用颜色；焦点可见、键盘可到达、图标有名称，禁用说明可读取。强调色不直接当作正文文字色；正式选型后核验文本对比度与明暗背景上的控件状态。

## 4. 逐模块构成与关键交互

### 4.1 内容协作智能体

共同保留五类信息：模块／项目导航、会话列表、聊天、当前成果画布、成果清单。A、B、C可改变摆放和默认折叠，但不能让用户无法辨认当前会话、当前成果与任务归属。

| 内容与入口 | 共同交互约束 | 风格适配 |
|---|---|---|
| 初始输入 | 突出当前项目、可选资源／技能；目标明确输入齐全则执行，模糊则澄清；模型名不替代工作目标 | A居中起稿；B提供创作目标捷径；C突出依据和最近会话 |
| 会话与消息 | 草稿按会话保留；异步执行显示排队／生成／成功／失败，无假百分比；后台完成不抢画布 | A常驻会话栏；B左侧显示业务任务，当前任务内会话从会话入口续做；C紧凑会话／状态列表 |
| Markdown | 仅AI生成且有权的.md可编辑；源码／渲染预览、显式保存、历史版本、未保存保护、冲突处理 | A文稿默认大区；B文稿模式替换视觉画布；C成果栏可展开专注编辑 |
| AI改稿 | 选中文本或当前版本提出修改；候选差异由人应用或放弃，应用为新版本 | 三方案保持同一文稿版本语义 |
| 图片局部提问 | 矩形锚点绑定图片版本；引用标签可移除；从消息回定位；不自动局部重绘 | B以大画布为主，A/C可放大画布 |
| 图像／视频生成 | 明示识别意图、源素材、专用生成服务和执行状态；视频缺图／多图先澄清；失败可修改后重试 | B底部成果条用于变体，A/C成果清单承接同一对象 |
| 沉淀技能 | 用户明确发起→经验草稿→编辑预览→确认保存至本项目；已有技能普通成员走更新申请 | 消息卡统一提供入口，不将按钮直接写成“自动发布技能” |
| 成果入库 | 选已保存版本手动入当前项目资源，入库失败不撤销文档保存 | 状态分别展示“已保存版本”“已入库” |

### 4.2 资源管理

页面由项目与模块导航、类型／分类、搜索筛选、资源列表或画廊、详情／预览构成。四类资源为图片、文档、音频、视频；保留既定分类及权限，不借本轮视觉重构新增跨项目分享语义。列表和画廊采用相同对象名称、归属、来源与状态；图片／视频可用缩略图，文档优先显示标题与类型，音频提供清楚的文件及播放状态。沿用D031，资源管理页不恢复“用于对话”按钮；引用从内容协作输入区的资源选择器发起。选择资源只确定操作对象，不自动开启聊天或触发生成。

主要动作为上传、预览、查看详情和获授权的维护；是否具备编辑、删除能力按对象与角色控制。协作输入区的“选择资源”读取当前项目可用集合，清楚显示选中项及失效项；资源管理中的原始文件维护与会话引用分离。上传中、解析中、失败、无权限、空分类、筛选无结果要能区分。A以资料阅读和查找为主，B以视觉素材浏览为主，C提高分类、属性与详情的同时可见程度。

### 4.3 智能体配置

保留“技能管理／提示词管理”明确子导航。技能清单显示名称、用途、类型／作用域、版本、来源和状态；全局技能只读，本项目技能按维护权限操作。详情展示Markdown规则正文和可访问的来源会话；查看技能权限不能赋予源会话访问权。提示词保留主约束、场景识别、参数抽取、技能路由、结果表达、人工确认六类及既有维护字段，不增加聊天中手动选择提示词的入口；不因竞品出现复杂工作流就新增工作流编辑器。

“配置＋试聊并排”是候选交互：可用于检查当前草稿的回答方式，清楚标注试用版本与“尚未生效”，不自动向项目成员发布。可用媒体工具信息可解释能生成什么、需要什么输入、当前是否可用；真实模型路由策略与管理权限继续按接入规则核验，不默认允许普通作者维护云端密钥、模型温度等技术参数。

对话创建的技能进入同一管理体系。更新候选、解析失败或审核驳回时，旧生效版本继续可用；保存、启用与更新审批要分别表达。A强调规则正文可读，B以用途卡片减轻寻找成本，C强调配置和调试结果同时可见。

## 6. 状态覆盖、验证与本轮边界

本轮重点是**10个主流程风格页面**，用相同业务场景比较三模块的整体设计。它不是既有67状态的全部重绘，不代表完整异常链路、服务接入或权限已验收；当前演示交互以交付入口的核验说明为准。原业务HTML、局域网服务与Figma未因本稿自动同步。

| 状态族 | 主流程风格稿要表达 | 方向选定后必须深化 |
|---|---|---|
| 外壳与导航 | 旧系统右上入口、项目、三模块、返回路径 | 无项目、登录过期、无权直达、切项目草稿保护 |
| 协作 | 当前会话、对话、文稿／媒体、成果清单 | 初始空态、加载、窄窗折叠、全屏返回、后台晚到结果 |
| Md编辑 | 预览／源码、保存动作和保存状态 | 空内容、未保存离开、保存失败、并发冲突、历史与AI差异 |
