## 1. 项目判断

项目定位是面向垂直行业培训内容的内部 AI 生产与协作平台。业务主线是：围绕单视频完成内容制作，再通过课程目录组织系列生产；人在关键环节确认质量，平台承接资料、任务、制作依据和成果，逐步积累可复用的公司能力。（§3—6）

当前材料已能支撑目标、主要场景、流程方向和部分业务边界讨论；尚不足以直接作为开发规格。专业成果的输入输出、制作工具衔接、任务状态、确认与返工规则，以及首版范围仍需补齐。这是对材料完整度的分析，不是对方案可行性的否定。

全文采用四类口径：**文档共识**表示来源已明确的方向或规则，不代表能力已实现；**候选方案**表示来源推荐但待验证；**待确认**表示尚未决策；**分析建议**表示本次梳理提出，需后续讨论。

## 3. 使用者与责任

| 参与者 | 来源已明确的职责 | 尚需明确的边界 |
|---|---|---|
| 任务负责人/制作人员 | 明确目标、选用方案、打磨并确认阶段成果、验收；一个负责人可承担多个确认 | 任务发起、分配、转交和交付责任；是否需独立审核人 |
| 文案同事 | 选用模板并参与内容制作，沉淀专业经验 | 文案、脚本、分镜分别由谁制作和确认 |
| 动画同事 | 维护可复用呈现模板与制作方案，参与专业制作 | 模板新增入口、维护流程及无匹配模板时的协作方式 |
| 系列负责人 | 查看系列整体进展，确认整体规划、首条效果和后续安排 | 是否与任务负责人为同一人；整体审核与交付标准 |
| AI | 基于需求与共享依据辅助规划、生成、检查和修改 | 各阶段效果、适用范围与人工补足方式 |
| 平台 | 承接任务和资料，衔接对话、技能、制作工具，保存成果与进展 | 工具接入方式、部署、数据访问和运行约束 |

依据：§4—7。上述业务分工不直接等同于系统权限角色；原文明确“个人聚焦不等于权限隔离”，复杂权限后置。

## 4. 核心场景与流程

### 4.1 单视频制作

明确需求、受众、目标与资料 → 选择呈现模板与风格 → 生成并确认文案 → 生成并确认脚本 → 生成并确认分镜 → 制作画面与声音 → 合成字幕及完整视频 → 人工审核 → 交付。（§4.2）

关键规则：

- 模板应在文案生成前参与约束；不应在制作完成后才补充风格要求。
- 文案、脚本、分镜、最终成片分别保留人工确认。
- AI 能力不足时，由人工或现有工具补足，不以全流程自动化为前提。
- 无合适模板时可提出新增；模板未定稿时允许先做草案样片，避免阻塞试制。
- 审核不通过时返回对应环节修改；哪些下游成果要重做、如何再次确认尚待定义。

### 4.2 系列课程生产

明确课程需求 → 选择模板与风格 → 规划并确认目录 → 从目录选一条试制 → 确认首条效果及后续安排 → 各条沿用单视频流程 → 系列整体验收与交付。（§4.3、6）

关键规则：

- 目录表达教学结构与顺序，视频条目关联制作任务。
- 首条可以直接成为系列中的一条；后续复用共同模板和制作依据，各条保留自身目标与内容。
- 视频可分配给不同人员并行制作，需同时支持系列总览与个人任务聚焦。
- 批量创建任务与批量执行生成是两件事；当前只保留批量支持方向，未确定启动及调度规则。
- 系列一致性和整套质量需要验证，但具体检查方式、标准与系统能力尚未确定。

## 6. 业务对象与关系

下表整理业务概念，供后续功能设计使用，不是已确定的数据表结构。（§4—6）

| 对象 | 当前可确定的关系 | 不能提前定死的内容 |
|---|---|---|
| 项目/协作范围 | 承载共同资料、模板和可用技能的共享方向 | 项目、课程包、课程、模块之间的完整层级 |
| 课程包与目录 | 课程包有可视目录，目录保留教学结构与顺序 | 目录调整后已有任务如何处理 |
| 视频条目与任务 | 视频条目关联单视频制作任务 | 是否允许一条对应多个任务或多个制作版本 |
| 阶段成果 | 文案、脚本、分镜需独立保存成果与确认状态 | 成果版本、重新确认、历史保留和多人修改规则 |
| 模板与技能 | 模板可关联多个技能、流程、素材；技能可以共用和跨阶段调用 | 版本、更新生效范围、管理审核机制 |
| 内容资产 | 文稿、素材、成片及依据关联任务或课程 | 元信息、搜索方式、重复文件及引用更新规则 |

特别注意：技能独立管理的概念，不等于首版必须建设独立技能库管理页面；模板与技能也不是一对一关系。

## 7. 当前边界

**已经明确的推进原则：** 人工逐步确认并推进，必要时人工接手；优先满足基本任务归属、进度/结果可见、进入任务制作和成果承接；先了解实际业务，再对齐流程、建设基础平台。（§4、6、8）

**不能视为已确定的实现：** 连续对话工作台界面、专业字段和产物格式、独立库管理模块、AI 推荐实现、完整层级结构、批量生成机制、首版功能清单和开发时间。（§5—8）

**明确后续再议或暂不深入：** 复杂权限、库版本审核、复杂批量调度、自动同步与影响识别、联动重做、复杂接手、排期优先级与通知统计；可点击且有分支的互动课件、自研学习平台对接暂不深入。（§7—8及沟通背景）

来源中的“下周沟通”和“下下周启动开发”是 2026-09-12 文档中的相对时间表述，不能据此认定会议已完成或开发日期已承诺。

## 9. 建议的验证口径

以下是将现有目标转为可检查结果的分析建议，尚非正式验收标准。真实视频及小系列试制应在需求了解后按需开展，不作为业务沟通前提。（§7.7、8）

| 验证方向 | 建议检查的结果 |
|---|---|
| 单视频闭环 | 一条真实需求能形成独立文案、脚本、分镜和成片，能识别对应人工确认结果，并完成交付 |
| 系列协作 | 目录保留结构与顺序，视频关联任务；负责人可看整体，制作人员可找到本人任务；首条经验能支持后续制作 |
| 返工可续做 | 针对一个真实问题，负责人能确定修改环节、完成修改并重新验收；不以自动联动重做为条件 |
| 资产可复用 | 完成任务后能够再次找到成果与制作依据，并用于续做或另一任务 |
| 降本提效 | 在内容和质量要求相近时，与历史任务对照人工投入、工具费用、总周期及返工情况，不预设改善比例 |
| 系列质量 | 人工检查人物、风格、术语、声音以及重复、遗漏和内容衔接；具体通过标准由业务确定 |
