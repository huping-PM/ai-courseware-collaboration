# 内容协作系统：产品开发计划

日期：2026-09-18。版本：v0.6。状态：已补充协作需求影响，执行顺序为建议，工期、人员、版本日期未正式排定。依据：[共识v0.45](../02_需求与共识/AI课件协作平台-业务流程与需求共识.md)、[页面功能v1.2](../03_功能设计/AI课件协作平台-页面与功能清单.md)。

本版替代原“4处修改＋3个主要新页、12包”的当前执行建议。原稿已[归档](../99_归档/2026-09-14-项目隔离与智能体重整前/README.md)，没有把原开发包记为已完成或取消中的实际任务，因为其尚未正式排期。

## 1. 修改与新增

| 对象 | 处理 | 工作范围 |
|---|---|---|
| 项目与导航 | 调整/核验 | 各项目相同模块，数据按项目切换与隔离；进入项目后可直接打开内容协作智能体 |
| 登录、项目设置、成员 | 优先复用 | 核对访问与权限，只补具体缺口；不新建项目定制模块体系 |
| 现图片/文件资源 | 改造并补齐类型支持 | 明确图片/文档/音频/视频四类；字段、上传、预览和归属按实际能力核验 |
| 音频/视频资源承载 | 依资源方案决定 | 单页方案新增类型页签与组件；分页面方案新增或复用音频/视频页，不重复建两套 |
| 智能体配置 | 新增模块 | 技能、提示词分别管理，通过左侧智能体配置展开子菜单进入各自列表与详情/编辑 |
| 内容协作智能体 | 新增模块 | 对话生成视频；四栏协作画布查看文档、图片、视频，支持手动保存至资源库 |
| 制作任务与计量 | 新增模块 | 主管派工、员工从任务进入创作、提交成品，以及按任务记录活动与模型用量；状态、多人和计量规则待Q19—Q21 |
| 协作数据看板 | 新增模块 | 汇总授权内容团队的成品、时长、Token及可下钻证据；统计及数据范围待Q20—Q22 |
| 权限与技能审核 | 扩展模块 | 各模块操作和数据权限；员工申请、主管审核更新全局技能，继续按项目启用 |
| 模板页、模型页、系列目录 | 不列本次必建 | 保留旧业务方向和必要底层能力，具体新增另议 |

2026-09-15当前原型交接：页面设计v0.5采用7个页面容器，资源单页四页签、配置左侧展开两个子菜单；按参考页面处理口径为已开发2页、待优化3页、待新建2页。已开发只表示参考页存在，不表示本项目已交付。该数量是具体原型方案，Q15尚未将单页方案定为正式开发决定。

## 2. 建议开发包

本次以“新版包A—I”标识，与旧稿包01—12区分，均未正式排期。历史研发覆盖与复用接口仍待核验，不按页面观察直接认定底层完成。

| 包 | 工作与交付物 | 依赖 | 验证条件 |
|---|---|---|---|
| A 项目隔离与基础核验 | 确认资源、配置、对话、结果归属和访问边界；核验现有项目/成员/存储接口，约定共用数据关系 | 用户框架已明确；Q01/Q04具体核验 | 两项目模块一致，查询、详情及生成请求不串项目；不预设独立部署 |
| B 四类型资源 | 选定单页或分页面方案，复用上传/列表能力，补四类类型化预览与必要维护 | A；Q15/Q07 | 四类资源可管理，选择/查看正确归属，无跨项目结果 |
| C 智能体配置 | 技能与提示词列表、详情、维护；明确其供智能体使用的规则 | A；Q16 | 两类对象都可管理，更新/调用符合确定规则，不默认为跨项目公共配置 |
| D 对话与生成接入 | 内容协作智能体主界面、项目内对话、生成要求与反馈；接入真实视频生成链路、状态与失败处理 | A；B/C接口约定，Q10/Q11 | 实际发起对话生成请求并获得真实结果；不以模拟视频验收 |
| E 右侧内容查看 | 四栏布局、生成项定位、三类内容查看、缩放/全屏及加载错误提示 | D结果协议 | 点击不同生成项显示对应内容，视频可播，退出画布全屏后保持对话与所选内容 |
| F 结果保存与资源衔接 | 实现D027已确认的手动保存，按Q17核对持久化、去重、权限与资源关联规则 | B/D/E；Q17 | 成果再次查找正确；手动入库的目标项目和资源类型一致 |
| G 真实试用与回归 | 验证隔离、配置、四类资源、视频生成及右侧展示；保留原系统功能回归 | 纳入范围各包就绪 | 正常/失败/切换项目场景通过，质量符合Q12明确标准 |
| H 任务管理与计量 | 主管在当前项目查看全部任务并创建、编辑、审核、删除、归档；员工仅查看本人任务，从任务进入创作、提交审核及可追溯证据 | A/D；Q19—Q21/Q25 | 任务可见范围正确；一次调用只计一次；人工活动、AI等待、自然周期不混算；删除/归档不抹去应保留证据；主管审核通过后完成并计入成品 |
| I 数据统计、权限与技能审核 | 项目内成员任务、平均完成时长、Token、完成率及分审核次数通过率；各模块权限；员工申请、主管审核发布技能版本 | A/C/H；Q20—Q24 | 看板与明细同口径；一次/二次/三次及以上审核通过正确分类；越权请求被拒绝；技能申请未通过或发布失败不影响当前版本 |

B/C可在A接口和范围明确后并行推进；D可先验证模型工具，界面联调需要资源与配置接口一致；E可依据约定结果协议推进，但真实内容展示验收须依D。F的手动保存能力已确认，持久化/去重/权限细则明确后实现。H依赖任务、会话和调用的统一归属；I依赖H提供可追溯数据与权限边界，技能审核可与C协同设计。上述只描述工作组织，不代表已分配人员。

## 3. 产品设计与原型交接

- 按当前协作框架输出导航和项目切换规则；制作任务是主管派工及员工创作入口，但自主创作是否保留待Q19。
- 当前原型按页面设计v0.5的单页四页签绘制；分页面方案仅作为Q15备选，不同时建设两套入口。
- 智能体配置的列表、详情、编辑字段和校验已在v0.3逐页落实；原型按既定演示参数绘制，调用及生效机制仍由Q16核对。
- 智能体原型重点验证对话、生成状态、选中结果、四栏画布查看三个类型及手动保存；不加入未确认的在线编辑器。
- 与业务提供的真实脚本、图片、视频样例联调，避免只看空壳界面。

## 4. 验收与待估算

需至少验证：两个项目同名数据的隔离、四类资源完整管理、技能和提示词分别维护、实际对话生成视频、右侧三类查看、生成失败不误报成功、切换项目不串上下文，以及派工权限、提交计数、用量防重、看板下钻和技能审核授权。

项目内具体角色、格式/限制、配置调用、会话持久化和成果归档仍有待确认项，见Q04/Q07/Q15—Q17；制作任务、计量、权限和技能审核见Q19—Q23。视频制作链路、质量与接口见Q03/Q10—Q12；未获得这些信息前不能完整估算生成与预览能力。

会中“本迭代1.0”仍是目标，截止日期、研发可用投入和历史覆盖见Q09/Q13。本计划只重整范围及依赖，未分配人名、工时或上线日期，未写入外部任务系统。确认后的详细功能与范围再进入实际排期。
