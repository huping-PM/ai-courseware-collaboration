## 2. 需求确认描述

**需求描述：** 用户在对话中明确引用一个已生成视频并提出分镜修改要求时，智能体应定位该视频对应的 HTML 源文件，完成修改并重新生成受影响的分镜视频。

**呈现/操作：**

1. 用户引用目标视频，直接描述要改的文案或画面。
2. 系统识别视频关联的分镜和源 HTML；能唯一定位时直接处理，不再把同任务所有 HTML 文件列给用户选择。
3. 修改并重新生成后，在原对话中展示新分镜视频及本次修改结果；无法唯一定位时只提示具体缺失信息。

## 4. 拟提交“需求描述”正文

### 背景与目标

用户在内容协作智能体对话中引用已生成的视频，要求修改其中一个分镜的文案或画面。现有截图显示：智能体在收到已引用的视频和明确的文案修改要求后，列出了多个“场景 HTML 工程包”，让用户手工选择源文件。用户已经指定视频时，系统应利用该视频与分镜源工程的关联信息定位受影响 HTML，并完成分镜视频的重新生成。

### 范围与规则

1. 适用于当前用户有权访问的、由 AI 课件协作流程生成且保存了可编辑 HTML 源工程的视频。用户可以通过会话引用视频成果，并以自然语言提出修改要求。
2. 系统应先限定到**被引用视频所属任务/会话及其分镜源工程**，识别目标视频与对应 HTML 文件或 HTML 工程包中的文件关系；修改要求指出具体文案或画面时，还应定位受影响的分镜。不得仅因文件名相似就修改其他任务或其他分镜。
3. 当视频、分镜和源 HTML 能唯一确定时，智能体直接修改对应源文件，执行现有分镜视频生成流程，返回新生成的视频成果，并在对话中说明修改了哪个分镜和哪些内容；不再列出全部 HTML 让用户选择。
4. 一个视频关联多个分镜时，先依据修改要求和源内容定位受影响分镜；如同一句文案出现在多个分镜、关联记录缺失或存在多个同等候选，智能体只就无法确定的分镜或源文件提问，并展示与该视频相关的候选，不得擅自修改。
5. 源文件修改或视频生成失败时，明确告知失败环节，保留原有可用视频，不把失败结果当作已完成；重新生成成功后，新成果仍关联原任务、分镜和所用源文件，便于后续继续修改。

### 本次边界

本项解决“已指定视频的源 HTML 定位与该分镜重生成”。不要求重新设计 HTML 模板、批量重制所有分镜或自动合成整片；已有视频生成流程与项目访问权限继续适用。

### 编码交接

研发需在现有系统中核查视频成果、分镜、HTML 工程包/源文件之间的实际关联字段和可编辑文件格式，再沿已有生成链路实现定位、修改和重生成。需要给出“同任务多 HTML、同一句文案多场景、源文件缺失、生成失败”四种验证证据；本稿不指定数据库表、文件路径或模型工具名。

## 5. 拟提交“验收标准”正文

1. 给定某任务有多个分镜 HTML 工程包、用户在会话中引用其中一个已生成视频并要求修改该视频内唯一出现的文案，当智能体处理请求时，应找到对应分镜源 HTML、只修改该分镜并重新生成其视频；对话中展示新视频和修改说明，不要求用户在全部 HTML 列表中二次选择。
2. 给定用户引用的目标视频关联多个分镜、修改指令能够在源内容中唯一定位其中一个分镜，当智能体处理请求时，应仅修改该分镜对应的 HTML 并重生成该分镜视频，其他分镜源文件和视频保持原有内容。
3. 给定关联记录缺失或修改内容同时匹配多个分镜，当智能体处理请求时，应指出无法唯一定位的原因并只提供相关候选供用户澄清；澄清前不修改源 HTML，也不启动重生成。
4. 给定源文件修改或重生成失败，当用户查看结果时，应看到失败环节与原视频仍可用的状态；不得将失败作业标记为成功的新分镜视频。
5. 给定用户引用无访问权限或其他任务的视频，当智能体处理请求时，不得读取或修改其 HTML 源文件，也不返回该视频的源文件列表。
